# Контейнеры решения (C4, уровень 2)

Версия 1.0 · Статус: Согласован · Автор: Архитектор решения

Диаграмма: `diagrams/c4-container.puml`.

Контейнер в терминах C4 — отдельно разворачиваемая часть: приложение, сервис, база данных, очередь. Диаграмма отвечает на вопрос **«из каких частей состоит решение и как они общаются»**. Системный аналитик использует её, чтобы понимать, в каком компоненте живёт требование и через какой интерфейс оно реализуется.

## Контейнеры

| Контейнер | Ответственность | Реализует ФТ | Новый / изменяемый |
|---|---|---|---|
| Портал IdM | UI для руководителей, ИБ, аудиторов | FR-13, FR-14, FR-22, FR-23 | Изменяемый (новые экраны заявок) |
| Ядро IdM (Core API) | Идентичности, роли, SoD, заявки, согласования, публичный REST API | FR-04, FR-06, FR-09 … FR-14, FR-18 | Изменяемый |
| Обработчик кадровых событий | Чтение топика, валидация, идемпотентность, DLQ | FR-01 … FR-03 | Новый |
| Планировщик | Отложенные операции и сверка | FR-05, FR-07, FR-08, FR-14 (эскалации) | Изменяемый |
| Сервис провижининга | Коннекторы, повторы, задачи в ServiceDesk | FR-15 … FR-17 | Изменяемый (новые коннекторы) |
| БД IdM | Операционные данные | — | Изменяемая (новые таблицы) |
| Журнал аудита | Неизменяемый журнал | FR-21, NFR-06 | Новый |
| Адаптер АБС | REST API над административными функциями АБС | FR-15 (АБС) | Новый, разрабатывает команда АБС |

## Ключевые архитектурные решения

Обоснования — в `05_adr.md`:

- ADR-001 — кадровые события через Kafka плюс ежедневная сверка;
- ADR-002 — учётные записи создаются заранее в заблокированном состоянии;
- ADR-003 — интеграция с АБС через отдельный адаптер, без прямого доступа к БД.
