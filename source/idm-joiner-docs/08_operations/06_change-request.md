# Запрос на изменение по итогам проблемы

Исправление после разбора проблемы — такое же изменение существующей системы, как любое другое: с анализом влияния, согласованием и порядком выкатки.

## CHG-01. Ограничение частоты запросов к целевым системам

| Поле | Значение |
|---|---|
| Основание | PRB-01, корневые причины 2–3 |
| Инициатор | СА IdM |
| Владелец решения | Владелец продукта IdM |
| Затрагивает | FR-16, контракт адаптера АБС (INT-05), НФТ, планировщик и сервис провижининга, мониторинг, тесты |
| Приоритет | Высокий: ближайший массовый приём — сентябрь 2027 |

## 1. Проблема и цель

При пиковом создании учётных записей IdM превышает ограничение частоты адаптера АБС, а одновременные повторы повторяют пик. Цель — чтобы при ограничении частоты задачи выполнялись с задержкой, а не уходили на ручную обработку.

## 2. Изменения

| Что | Сейчас | Станет |
|---|---|---|
| Контракт адаптера, `POST /users` и другие операции | 503 — «АБС недоступна»; ограничения частоты не описаны | 429 при превышении лимита, заголовок `Retry-After`; лимит 30 запросов в минуту на клиента указан в описании API |
| FR-16, раздел 2.3 «Политика повторов» | Повторы через 1 и 5 минут, всего 3 попытки | При 429 — повтор не раньше `Retry-After`, такие повторы не считаются в 3 попытки (до предела в 60 минут); к интервалам повторов добавляется случайная задержка до 30 секунд |
| Планировщик, создание учётных записей | Все задачи на 09:00 | Не более заданного числа запросов в минуту на систему; лимит хранится в настройках коннектора |
| Новое НФТ | — | Адаптер АБС обрабатывает не менее 30 запросов в минуту от IdM; пиковое создание (300 сотрудников в день, NFR-03) выполняется до 12:00 дня создания |
| Мониторинг | ALR-04 добавлен | Метрика «ответы 429 по системам»; ALR-02 не учитывает 429, пока задачи укладываются в срок |
| Тесты | TC-12 — недоступность АБС | Новый тест: 429 с `Retry-After` — задачи выполнены с задержкой, MANUAL не создаются; нагрузочный тест потока в АБС |

## 3. Анализ влияния

| Слой | Затронуто | Что меняется |
|---|---|---|
| Требования | Да | FR-16, новое НФТ, комментарий к NFR-11 |
| Статусная модель задачи провижининга | Нет | RETRY_WAIT используется так же; меняется только расчёт времени следующей попытки |
| Контракт адаптера | Да | Новый ответ 429 и заголовок `Retry-After` |
| Сервис провижининга | Да | Обработка 429 и `Retry-After`, случайная задержка |
| Планировщик | Да | Ограничение скорости по системам |
| Другие коннекторы (AD, Exchange) | Нет | Правило общее, но лимиты у них не настроены |
| Мониторинг | Да | Новая метрика, правило ALR-02 |
| Тесты | Да | Новый тест, нагрузочный тест потока |
| Документация | Да | ФТ, НФТ, контракт, runbook RB-02 |
| Обратная совместимость | Да | Если адаптер начнёт отвечать 429 раньше, чем IdM научится его обрабатывать, IdM сочтёт 429 технической ошибкой (как сейчас по FR-16) и повторит через 1 и 5 минут — инцидент повторится |

## 4. Порядок выкатки

1. IdM: поддержка 429 и `Retry-After`, ограничение скорости в планировщике (релиз IdM).
2. Адаптер АБС: ответ 429 вместо 503 при превышении лимита (релиз адаптера) — **только после** шага 1.
3. Обновление контракта (версия 1.1.0) и документации.
4. Проверка на продуктиве: в ближайший понедельник с массовым созданием — ответы 429 есть, задач MANUAL по АБС нет, создание закончено до 12:00.
