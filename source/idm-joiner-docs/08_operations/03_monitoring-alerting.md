# Мониторинг и алерты

Основа — NFR-11 (метрики очередей, задержки, ошибок коннекторов) и требование трассировки событий. Мониторинг отвечает на два вопроса: **работает ли автоматизация сейчас** и **успеют ли доступы к ближайшей дате выхода**.

## 1. Метрики

| Метрика | Что показывает | Источник |
|---|---|---|
| `event_processing_seconds` | Задержка обработки кадрового события (NFR-01) | Обработчик событий |
| Отставание группы потребителей `hr.employee.events.v1` | Не копятся ли непрочитанные события | Kafka |
| Новые сообщения в `hr.employee.events.v1.dlq` | Некорректные события (FR-02) | Kafka |
| Задачи провижининга по статусам и системам | Сколько в RETRY_WAIT и MANUAL | БД IdM |
| Доля ошибок коннектора за час по системам | Здоровье интеграций (NFR-11) | Сервис провижининга |
| Ответы целевых систем по кодам HTTP | 4xx и 5xx в разрезе систем | Сервис провижининга |
| Выполнение активаций к 07:00 по поясам | Готовность к первому дню (FR-08) | Планировщик |
| Расхождения ежедневной сверки | Потерянные события (FR-05) | Планировщик |

## 2. Алерты

| ID | Условие | Приоритет | Кому | Что делать |
|---|---|---|---|---|
| ALR-01 | Задержка обработки событий > 15 минут (NFR-11) | P2 | Дежурный L2 | Проверить отставание потребителя и обработчик событий |
| ALR-02 | Ошибки коннектора > 5% за час (NFR-11) | P2 | Дежурный L2 | RB-02 |
| ALR-03 | Новое сообщение в DLQ | P3 | Дежурный L2 | RB-01 |
| ALR-04 | Более 3 задач MANUAL по одной системе за час | P2 | Дежурный L2, владелец продукта | RB-02; добавлен по итогам PRB-01 |
| ALR-05 | Активация не выполнена к 07:15 местного времени | P2 | Дежурный L2 | RB-04 |
| ALR-06 | Расхождения ежедневной сверки | P3 | Дежурный L2 | RB-05 |

Алерт без процедуры бесполезен: у каждого алерта есть ссылка на процедуру runbook.

## 3. Логи и трассировка

- **Структурированные логи** (JSON): время, уровень, компонент, `traceId`, `eventId`, `personId`, `taskId`, система, HTTP-код, длительность, сообщение.
- **Без ПДн:** в логах — идентификаторы, без ФИО, телефона и паспортных данных (NFR-09).
- **Сквозная трассировка:** `traceId` присваивается при получении кадрового события, передаётся во все вызовы целевых систем в заголовке `traceparent` (W3C Trace Context) и записывается в журнал аудита (`audit_event.correlation_id`). По одному `traceId` можно собрать путь события через все системы.
- **Хранение логов** — 30 дней в системе логирования; журнал аудита — 5 лет (NFR-06).

## 4. Дашборд дежурного

Одна страница: события за сутки и задержка; DLQ; задачи по статусам и системам; ошибки коннекторов по часам; ближайшие даты выхода и готовность доступов к ним.
