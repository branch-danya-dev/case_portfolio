# Тестовые сценарии

Версия 1.0 · Автор: QA · Источники: ФТ, статусные модели, sequence-диаграммы

Тесты выводятся из требований и моделей: каждый альтернативный поток use case, каждый переход статусной модели и каждая ветка `alt` на sequence-диаграмме дают как минимум один тест.

## 2. Пример подробного тест-кейса

### TC-12. Недоступность АБС при создании пользователя

| Поле | Значение |
|---|---|
| Требования | FR-16, сценарий SEQ-02 |
| Предусловия | Сотрудник «Тестов Тест Тестович», дата выхода D; заглушка адаптера АБС настроена возвращать 503; учётные записи в статусе PLANNED |
| Тестовые данные | `personId = P-T-012`, подразделение 1601, должность 40110 |

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Сдвинуть время стенда на дату создания (D − 3 рабочих дня) | Задачи провижининга запущены |
| 2 | Проверить задачи AD и Exchange | Статус DONE, учётные записи CREATED_DISABLED |
| 3 | Проверить задачу АБС через 1 минуту | `attempts = 1`, статус RETRY_WAIT |
| 4 | Сдвинуть время ещё на 5 минут | `attempts = 3`, статус MANUAL, заполнен `sd_ticket_id` |
| 5 | Проверить ServiceDesk | Задача в группе «Администраторы АБС» с данными пользователя и текстом ошибки |
| 6 | Проверить почту руководителя | Письмо о ручном исполнении доступа в АБС |
| 7 | Проверить запросы в журнале заглушки | Все три запроса с одинаковым `Idempotency-Key` |
| 8 | Закрыть задачу в ServiceDesk с `externalId` | Webhook принят (204); задача DONE; учётная запись АБС CREATED_DISABLED |
| 9 | Проверить журнал аудита | Записи по каждой попытке, переводу в MANUAL и закрытию |
