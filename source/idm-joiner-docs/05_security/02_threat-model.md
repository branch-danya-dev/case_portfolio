# Модель угроз и доступ к API

Версия 1.0 · Статус: Согласован · Автор: СА, инженер ИБ · Утверждает: CISO

Требования ИБ (`01_security-requirements.md`) отвечают на вопрос «что должно быть». Этот документ отвечает на вопрос **«от чего защищаемся и где именно»**: границы доверия, угрозы по STRIDE, матрица доступа к API IdM, сервисные учётные записи и сроки жизни учётных данных. Угрозы со статусом «Предложено» вынесены на согласование с владельцем продукта и ИБ.

## 1. Границы доверия

Граница доверия (trust boundary) — место, где данные переходят между зонами с разным уровнем доверия. На каждой границе нужно ответить, кто вызывающий и можно ли ему верить.

| Граница | Кто пересекает | Как проверяется вызывающий |
|---|---|---|
| Браузер руководителя → портал IdM | Пользователь | SSO (Kerberos, AD), токен портала (SEC-10) |
| HRMS → Kafka → IdM | Кадровые события | ACL на запись в топик только для HRMS, TLS + SASL |
| ServiceDesk → IdM API | Системный клиент | mTLS + OAuth 2.0 client credentials (SEC-08) |
| IdM → AD, Exchange | Коннекторы IdM | Сервисные учётные записи (SEC-07) |
| IdM → адаптер АБС | Коннектор IdM | mTLS + OAuth 2.0 client credentials |
| IdM → SMS-шлюз | Сервис провижининга | Ключ API |
| IdM → SIEM | События аудита | ACL на запись в топик аудита |

## 2. Угрозы (STRIDE)

STRIDE — шесть категорий угроз: подмена (Spoofing), изменение (Tampering), отказ от авторства (Repudiation), раскрытие информации (Information disclosure), отказ в обслуживании (Denial of service), повышение привилегий (Elevation of privilege).

| ID | Категория | Угроза | Мера | Статус |
|---|---|---|---|---|
| THR-01 | Подмена | Ложное кадровое событие в шине — создаются учётные записи несуществующему сотруднику | ACL на запись в топик только для HRMS; TLS + SASL; ежедневная сверка с HRMS (FR-05) | Есть |
| THR-02 | Подмена | Чужая система вызывает закрытие задачи ручного исполнения — учётная запись создаётся без исполнения | mTLS + OAuth 2.0, scope `idm.manual-tasks.write` только у ServiceDesk (SEC-08) | Есть |
| THR-03 | Изменение | Запись в журнале аудита изменена или удалена, чтобы скрыть выдачу прав | Журнал только на добавление (append-only); копия в SIEM (SEC-05, INT-09) | Есть |
| THR-04 | Отказ от авторства | Согласующий утверждает, что не одобрял критичное полномочие | Журнал аудита: кто, что, основание, время (FR-21); вход только через SSO | Есть |
| THR-05 | Раскрытие | Руководитель перебором `employeeNumber` смотрит доступы чужих сотрудников | Проверка подчинённости на сервере для каждого запроса (SEC-10); ответ не раскрывает, существует ли сотрудник | Есть |
| THR-06 | Раскрытие | ПДн попадают в логи и системы мониторинга | Логи с идентификаторами вместо ФИО и телефона (NFR-09, `08_operations/03_monitoring-alerting.md`) | Есть |
| THR-07 | Раскрытие | Перехват первичного пароля | Одноразовый пароль только по SMS, смена при первом входе (SEC-04) | Есть |
| THR-08 | Отказ в обслуживании | Массовые запросы к API портала (ошибка скрипта или злоупотребление) мешают работе руководителей | Ограничение частоты запросов на пользователя, ответ 429 | Предложено |
| THR-09 | Повышение привилегий | Компрометация коннектора AD даёт права администратора домена | Минимальные права сервисной учётной записи, административные группы — только через PAM (SEC-07, SEC-11) | Есть |
| THR-10 | Повышение привилегий | Руководитель запрашивает полномочие для себя или согласует собственную заявку | Заявитель не может быть согласующим своей заявки; заявка на себя — через своего руководителя | Предложено |
| THR-11 | Повышение привилегий | Учётная запись нового сотрудника используется до его выхода | Учётные записи заблокированы до дня выхода (SEC-03, ADR-002) | Есть |

## 3. Матрица доступа к API IdM

Контракт — `04_integrations/api/idm-api.openapi.yaml`. Проверка схемы безопасности (кто ты) обязательна, но недостаточна: для каждой операции нужна ещё **проверка на уровне объекта** — можно ли этому пользователю работать именно с этим сотрудником или заявкой.

| Операция | Кто вызывает | Схема | Проверка на уровне объекта |
|---|---|---|---|
| `GET /employees/{employeeNumber}/access` | Руководитель, ИБ, аудитор | `portalAuth` | Руководитель — только подчинённые (SEC-10); ИБ и аудитор — все, только чтение |
| `GET /catalog/entitlements` | Руководитель | `portalAuth` | Каталог без административных групп (SEC-11) |
| `POST /access-requests` | Руководитель | `portalAuth` | Сотрудник — подчинённый заявителя; не сам заявитель (THR-10) |
| `GET /access-requests/{requestId}` | Заявитель, согласующие | `portalAuth` | Заявитель или согласующий этой заявки |
| `POST /access-requests/{requestId}/items/{itemId}/decisions` | Согласующий | `portalAuth` | Пользователь назначен согласующим этой позиции; не заявитель (THR-10) |
| `POST /manual-tasks/{taskId}/completion` | ServiceDesk | `serviceAuth`, scope `idm.manual-tasks.write` | Задача в статусе ожидания исполнения |

Отказ по схеме — 401 (нет или недействителен токен) или 403 (нет прав на операцию). Отказ на уровне объекта для чужого сотрудника — 404, чтобы не раскрывать его существование (THR-05).

## 4. Сервисные учётные записи

| Учётная запись | Система | Права | Секрет | Владелец |
|---|---|---|---|---|
| Коннектор AD | AD | Создание пользователей и управление группами только в OU пользователей (SEC-07) | Пароль в хранилище секретов | Администраторы AD |
| Коннектор Exchange | Exchange | Создание почтовых ящиков и делегирование доступа | Пароль в хранилище секретов | Администраторы почты |
| Клиент адаптера АБС | Адаптер АБС | Пользователи и роли АБС, без административных ролей | Сертификат mTLS + `client_secret` | Команда АБС |
| Клиент ServiceDesk | IdM API | Только scope `idm.manual-tasks.write` | Сертификат mTLS + `client_secret` | Служба поддержки |
| Публикатор HRMS | Kafka | Запись только в `hr.employee.events.v1` | Учётные данные SASL | Команда интеграции |

Правила: сервисная учётная запись не используется людьми для входа; у каждой есть владелец; права пересматриваются ежегодно вместе с владельцем.

## 5. Сроки жизни учётных данных

| Что | Срок | Что происходит по истечении | Как отозвать досрочно |
|---|---|---|---|
| Токен доступа портала | 15 минут | Портал обновляет токен, пока сессия активна | Завершение сессии |
| Сессия портала | 8 часов; 30 минут бездействия | Повторный вход через SSO (без ввода пароля в домене) | Блокировка учётной записи в AD |
| Токен системного клиента (client credentials) | 5 минут | Клиент получает новый токен | Отзыв клиента на сервере авторизации |
| `client_secret` и сертификаты mTLS | 1 год | Плановая замена за 1 месяц до истечения, без простоя | Отзыв сертификата, новый секрет |
| Пароли сервисных учётных записей | По политике паролей банка | Замена через хранилище секретов | Смена пароля |
| Одноразовый пароль (FR-20) | До первого входа | Смена при первом входе | Сброс через поддержку после идентификации |

При увольнении или блокировке сотрудника в AD портал перестаёт выдавать новые токены, а действующий токен доступа истекает не позже чем через 15 минут. Это остаточный риск, который ИБ приняла.

## 6. Открытые вопросы

| Вопрос | Кто решает | Срок |
|---|---|---|
| Лимит запросов к API портала на пользователя (THR-08) | Архитектор, ИБ | До приёмочных испытаний |
| Правило «заявитель не согласует свою заявку» в ФТ и тестах (THR-10) | Владелец продукта, ИБ | До приёмочных испытаний |
| Срок действия одноразового пароля, если сотрудник не вышел в первый день | ИБ, HRD | До пилота |
