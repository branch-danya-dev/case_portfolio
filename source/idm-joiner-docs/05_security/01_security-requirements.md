# Требования информационной безопасности

Версия 1.0 · Статус: Согласован · Автор: Инженер ИБ (при участии СА) · Утверждает: CISO

Требования ИБ формулирует служба ИБ, но системный аналитик обязан встроить их в ФТ, НФТ, контракты и тесты. На практике этот документ собирается из внутренних стандартов банка, ГОСТ Р 57580.1 (меры по управлению учётными записями и правами логического доступа) и 152-ФЗ.

| ID | Требование | Где реализовано |
|---|---|---|
| SEC-01 | Принцип минимальных привилегий: сотрудник получает только полномочия своей роли и согласованных заявок | Ролевая модель, FR-10, FR-13, FR-14 |
| SEC-02 | Разделение полномочий (SoD) проверяется автоматически до выдачи | FR-12, `04_role-model.md` раздел 5 |
| SEC-03 | Учётные записи не активны до первого рабочего дня | FR-07, FR-08, ADR-002 |
| SEC-04 | Первичный пароль одноразовый, передаётся только по SMS, меняется при первом входе; пароль не передаётся по e-mail и не отображается в интерфейсах | FR-20, BRL-08 |
| SEC-05 | Каждая операция фиксируется в неизменяемом журнале аудита с основанием; хранение — не менее 5 лет; выгрузка в SIEM | FR-21, NFR-06, INT-09 |
| SEC-06 | Изменения ролевой модели и SoD-правил — только после согласования ИБ, с записью в журнал | UC-07 |
| SEC-07 | Сервисные учётные записи коннекторов имеют только необходимые права (например, коннектор AD — создание пользователей и управление группами только в OU пользователей, без прав на административные группы); секреты — в хранилище секретов | NFR-08 |
| SEC-08 | Все интеграции — TLS 1.2+; API — mTLS + OAuth 2.0 | NFR-07 |
| SEC-09 | Минимизация ПДн: в IdM не передаются паспортные данные, дата рождения, адрес; телефон не передаётся в AD | NFR-09, `03_data-mapping.md` |
| SEC-10 | Доступ к порталу — только через SSO; руководитель видит только подчинённых | NFR-07, API `getEmployeeAccess` |
| SEC-11 | Административные группы AD и привилегированные роли не входят в каталог полномочий IdM и выдаются только через PAM | Ролевая модель, устав (вне скоупа) |
| SEC-12 | Отчёт о «поздних» приказах (меньше 2 рабочих дней до выхода) ежемесячно направляется HRD и CISO | Риск R-01 |

## Модель угроз (кратко)

| Угроза | Мера |
|---|---|
| Учётная запись нового сотрудника используется до его выхода | SEC-03 |
| Перехват первичного пароля | SEC-04 |
| Компрометация коннектора даёт права администратора домена | SEC-07, SEC-11 |
| Ложное кадровое событие (подмена в шине) | ACL на запись в топик только для HRMS, TLS + SASL, сверка с HRMS (FR-05) |
| Накопление прав при переводах | Риск R-04 принят до волны 2 |
