# Карта интеграций

Версия 1.0 · Статус: Согласован · Автор: Системный аналитик · Утверждает: Архитектор решения, владельцы смежных систем

Карта интеграций — реестр всех потоков данных между IdM и внешними системами. Для каждого потока фиксируется: кто источник и приёмник, что передаётся, как (протокол, формат, режим), как часто и сколько, где контракт и что происходит при ошибке. По этому документу смежные команды планируют свою работу.

| ID | Источник → Приёмник | Что передаётся | Протокол / формат | Режим | Частота / объём | Контракт | Ошибки | Владелец на другой стороне |
|---|---|---|---|---|---|---|---|---|
| INT-01 | HRMS → Kafka → IdM | Кадровые события HIRE, HIRE_CHANGED, HIRE_CANCELLED | Kafka, JSON | Асинхронно, at-least-once | По факту; до 300/день | `api/hr-events.asyncapi.yaml` | Невалидные — в DLQ + инцидент; дубли — по `eventId` | Команда HRMS, команда интеграции |
| INT-02 | IdM → HRMS | Полный срез сотрудников (действующие и планируемые) | REST, JSON, постранично | Синхронно, pull | Ежедневно 02:00; ~4 000 записей | Контракт HRMS (ведёт команда HRMS) | Повтор в 03:00, затем алерт | Команда HRMS |
| INT-03 | IdM → AD | Учётные записи, блокировка, группы, пароль | LDAPS (636) | Синхронно | По задачам; до 300 учётных записей/день | Схема атрибутов в `03_data-mapping.md` | Политика повторов FR-16 | Администраторы AD |
| INT-04 | IdM → Exchange | Почтовые ящики, доступ к общим ящикам | PowerShell Remoting (`Enable-Mailbox`, `Add-MailboxPermission`) | Синхронно | По задачам | `03_data-mapping.md` | Политика повторов FR-16 | Администраторы почты |
| INT-05 | IdM → Адаптер АБС | Пользователи АБС, статус, роли | REST, JSON, mTLS | Синхронно, идемпотентно | По задачам | `api/abs-adapter.openapi.yaml` | Политика повторов FR-16, `Idempotency-Key` | Команда АБС |
| INT-06 | IdM ↔ ServiceDesk | Создание задач ручного исполнения; уведомление о закрытии (webhook) | REST, JSON | Синхронно | По необходимости; ~150 задач/мес. | API ServiceDesk; webhook — `api/idm-api.openapi.yaml` | Повторы; при недоступности — алерт сопровождению IdM | Служба поддержки |
| INT-07 | IdM → SMS-шлюз | Одноразовый пароль | REST, JSON | Синхронно | В день выхода; до 300/день | API SMS-шлюза | 3 повтора, затем уведомление руководителю: сотрудник получает пароль в поддержке после идентификации | Департамент ИТ |
| INT-08 | IdM → Exchange (SMTP) | Уведомления руководителям и согласующим | SMTP | Асинхронно | ~10 писем на сотрудника | Шаблоны писем | Повтор очереди SMTP | Администраторы почты |
| INT-09 | IdM → Kafka → SIEM | События журнала аудита | Kafka, JSON (CEF-поля) | Асинхронно | Все операции IdM | Схема `idm.audit.v1` (ведёт ИБ) | Буфер в журнале, CDC догоняет | Департамент ИБ |

## Принципы

- **Синхронно или асинхронно.** Асинхронно там, где источник не должен зависеть от доступности приёмника (HRMS не должна ждать IdM). Синхронно там, где нужен результат сразу и есть повторы (провижининг).
- **Идемпотентность.** Каждый повторяемый вызов должен давать тот же результат: ключ `eventId` на входе, `Idempotency-Key = taskId` на выходе.
- **Владелец контракта.** Контракт описывает та сторона, которая предоставляет API: HRMS — формат событий (но согласует его с IdM), IdM — свой API и webhook, команда АБС — API адаптера (по требованиям СА проекта).
