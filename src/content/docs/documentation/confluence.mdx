<Brief>

Confluence — самая распространённая вики для проектной документации в компаниях, где работают с Jira. Хорошее пространство проекта отличается **предсказуемой структурой** (дерево по слоям), **шаблонами**, **статусами и владельцами** страниц, **связью с Jira** и понятным **процессом ревью**.
Плохое — свалкой страниц «Новая страница (2)», в которой актуальное не отличить от устаревшего.

</Brief>

## Когда применять

| Confluence удобен | Лучше другое |
|---|---|
| Бизнес и ИТ правят и комментируют одни документы | Контракты и модели, которые меняются вместе с кодом → git |
| Нужна связь требований с задачами Jira | Строгая модель требований с трассировкой в CASE-средстве (требование заказчика) |
| Быстро начать, без настройки сборки | Документ, который должен быть подписан как файл → экспорт в PDF / Word |

## Как делать

<Steps>

1. **Дерево страниц по слоям проекта:** «О проекте» → «Бизнес» → «Требования» → «Архитектура» → «Интеграции» → «ИБ» → «Внедрение» → «Тестирование» → «Эксплуатация» → «Архив».

2. **Стартовая страница** — навигация, маршрут чтения, ключевые контакты, ссылки на доски Jira.

3. **Шаблоны** для повторяющихся страниц: функция, интеграция, ADR, протокол встречи.

4. **Свойства страницы** в шапке: статус, версия, владелец, утверждающий, дата. Отчёт по свойствам — реестр документов на стартовой странице.

5. **Связь с Jira:** на странице ФТ — список связанных историй; в историях — ссылка на страницу.

6. **Ревью:** встроенные комментарии к фрагментам, статус «На согласовании», явное утверждение (комментарием, задачей или через приложение для согласований).

7. **Устаревшее — в архив** с пометкой, а не удаление. История версий страницы хранит изменения.

</Steps>

## Нотация: макросы и практики

| Макрос / функция | Для чего |
|---|---|
| Свойства страницы (Page Properties) | Шапка документа: статус, владелец, версия |
| Отчёт свойств страниц (Page Properties Report) | Сводная таблица документов по меткам — реестр |
| Задачи Jira (Jira issues) | Список связанных задач по запросу на странице |
| Статус (Status) | Цветная метка: черновик, на согласовании, согласовано |
| Оглавление (Table of contents) | Навигация по длинной странице |
| Раскрывающийся блок (Expand) | Детали и примеры, не загромождающие страницу |
| Фрагмент и вставка фрагмента (Excerpt / Excerpt include) | Одно определение — на нескольких страницах без копирования |
| Метки (labels) | Группировка страниц: `фт`, `интеграция`, `adr` |
| Встроенные комментарии | Ревью конкретных фраз |
| История страницы | Кто, когда и что изменил; сравнение версий |

**Диаграммы:** для draw.io, PlantUML, Mermaid существуют приложения Marketplace, которые позволяют хранить диаграмму на странице в редактируемом виде. Набор доступных приложений зависит от вашего экземпляра Confluence — уточните у администраторов.

```text title="Пример дерева пространства проекта"
IDM-JOINER
├── О проекте (навигация, контакты, реестр документов)
│   ├── Устав
│   ├── Стейкхолдеры и RACI
│   └── Глоссарий
├── Бизнес: AS-IS, TO-BE, gap-анализ, БТ
├── Требования: use cases, ФТ (страница на функцию), НФТ, ролевая модель, трассировка
├── Архитектура: C4, модель данных, статусы, ADR (страница на решение)
├── Интеграции: карта, страница на интеграцию, маппинг, ссылки на контракты
├── ИБ · Внедрение · Тестирование
├── Протоколы встреч (по датам)
└── Архив
```

## Пример из кейса IDM-JOINER

Структура кейса один к одному ложится на пространство Confluence — папки `00_project` … `07_testing` становятся разделами, а файлы — страницами. Шпаргалка кейса прямо говорит, что нумерация папок — условность, а структуру в компании обычно задаёт **шаблон пространства Confluence или внутренний регламент**.

Связь с Jira из кейса: <CaseRef href="/case/02-requirements/backlog/" id="Бэклог">бэклог</CaseRef> — «в Jira каждая история — отдельная задача со ссылкой на ФТ в Confluence. ФТ остаются долгоживущим описанием системы, истории — единицами работы». А <CaseRef href="/case/02-requirements/traceability-matrix/" id="Трассировка">трассировку</CaseRef> на малом проекте можно вести связями задач в Jira вместо отдельной таблицы.

## Типичные ошибки

| Ошибка | Чем плохо | Как правильно |
|---|---|---|
| Нет структуры, страницы где попало | Ничего не найти, дубли | Дерево по слоям и стартовая страница |
| Нет статуса и владельца | Неясно, можно ли опираться | Свойства страницы |
| Копирование одного текста на многие страницы | Расхождения | Фрагмент и вставка фрагмента, ссылки |
| Требования только в комментариях задач Jira | Знания теряются после закрытия задачи | Долгоживущее — в Confluence, задачи ссылаются |
| Удаление устаревших страниц | Потеря истории решений | Архив с пометкой |
| Диаграммы картинками без исходника | Никто не может исправить | Редактируемые диаграммы или исходник рядом |
