<Brief>

**Docs-as-code** — документацию ведут теми же инструментами, что и код: текст в **Markdown** (или AsciiDoc) в **git**, изменения через **pull request с ревью**, диаграммы — **текстом** (Mermaid, PlantUML), контракты — файлами OpenAPI / AsyncAPI, сайт собирается **автоматически**, проверки — в CI.
Главная польза — документация **меняется вместе с кодом** и видна история «что, когда и почему».
Главная цена — порог входа для людей вне разработки.

</Brief>

## Когда применять

| Подходит | Не подходит / лучше вики |
|---|---|
| Техническая документация: контракты, модели, архитектура, ADR | Документы для бизнеса, которые правят люди без git |
| Команда уже живёт в git и pull request | Нужны совместное редактирование и комментарии «на полях» |
| Документацию важно версионировать вместе с релизами | Корпоративный стандарт требует Confluence / Word |
| Нужны автоматические проверки (ссылки, контракты, орфография) | — |

Частый гибрид: бизнес-документы — в Confluence, технические (контракты, ADR, модели) — в git, со ссылками друг на друга.

## Как делать

<Steps>

1. **Репозиторий и структура:** папки по слоям, как в кейсе, `README` с навигацией.

2. **Формат:** Markdown; диаграммы — Mermaid или PlantUML в файлах рядом с текстом; контракты — YAML.

3. **Процесс:** любое изменение — ветка и pull request; ревью аналитиком, архитектором, разработкой.

4. **Проверки в CI:** валидность OpenAPI / AsyncAPI, битые ссылки, стиль и орфография, сборка диаграмм.

5. **Публикация:** генератор статического сайта собирает документацию при каждом слиянии.

6. **Правило DoD:** изменение кода, которое меняет поведение, сопровождается изменением документации в том же pull request.

</Steps>

## Нотация: инструменты и практики

| Задача | Инструменты (примеры) |
|---|---|
| Формат текста | Markdown, AsciiDoc |
| Диаграммы как код | Mermaid, PlantUML, Structurizr DSL (C4) |
| Контракты | OpenAPI, AsyncAPI, JSON Schema |
| Генераторы сайтов | Astro Starlight, MkDocs, Docusaurus, Antora, Sphinx |
| Проверка текста | markdownlint, Vale (стиль и терминология) |
| Проверка контрактов | Линтеры OpenAPI / AsyncAPI (например, Spectral) |
| Проверка ссылок | Валидаторы ссылок в сборке |

```text title="Пример структуры репозитория документации"
docs/
├── README.md                 навигация и маршрут чтения
├── 00_project/               устав, стейкхолдеры, глоссарий
├── 02_requirements/          ФТ, НФТ, use cases
├── 03_architecture/
│   ├── adr/                  ADR-001.md, ADR-002.md…
│   └── diagrams/             *.puml, *.mmd
├── 04_integrations/
│   └── api/                  *.openapi.yaml, *.asyncapi.yaml
└── CHANGELOG.md
```

| Плюсы | Минусы |
|---|---|
| История, дифф, автор каждого изменения | Порог входа: git, Markdown, pull request |
| Ревью как у кода | Неудобно комментировать «на полях» для бизнеса |
| Документация рядом с кодом и меняется вместе с ним | Нужна настройка сборки и CI |
| Автоматические проверки | Сложнее с таблицами и визуальным форматированием, чем в вики |
| Диаграммы не «разъезжаются» и их дифф читаем | — |

## Пример из кейса IDM-JOINER

Архив <CaseRef href="/case/" id="Кейс">IDM-JOINER</CaseRef> — пример docs-as-code: Markdown по слоям `00_project` … `07_testing`, BPMN как XML, диаграммы на PlantUML, контракты на OpenAPI и AsyncAPI, `README` с навигацией.

**Этот справочник — тоже docs-as-code:** страницы в MDX, диаграммы Mermaid и PlantUML рендерятся при сборке, при каждой сборке проверяются ссылки и отсутствие внешних загрузок, история изменений — в git. Страницы кейса генерируются из исходного архива скриптом, а ID требований автоматически превращаются в ссылки.

## Типичные ошибки

| Ошибка | Чем плохо | Как правильно |
|---|---|---|
| Документация в отдельном репозитории «потом догоним» | Расходится с кодом | Изменение документации в том же pull request |
| Диаграммы картинками в git | Нет диффа, правки только у автора | Диаграммы текстом |
| Нет проверок в CI | Битые ссылки и невалидные контракты | Линтеры и валидаторы |
| Все документы — в git, включая бизнес | Бизнес не участвует в ревью | Гибрид с вики |
| Нет навигации | Документы есть, найти нельзя | README, сайт, поиск |
