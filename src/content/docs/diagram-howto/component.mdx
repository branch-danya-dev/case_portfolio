Теория — [UML: компоненты и развёртывание](/diagrams/component-deployment/).

## Алгоритм построения

<Steps>

1. **Компоненты** — модули с одной ответственностью; имя отражает ответственность.
2. **Предоставляемые интерфейсы** — что компонент даёт другим (API, события).
3. **Требуемые интерфейсы** — что ему нужно.
4. **Соедините** требуемые с предоставляемыми; подпишите, зачем.
5. **Группировка** — пакет или граница системы.
6. **Когда остановиться:** понятно, через какой интерфейс реализуется каждое требование и что сломается при изменении интерфейса.

</Steps>

## Синтаксис

**Mermaid не поддерживает UML component.** Для обзора архитектуры в Mermaid используйте C4 (C4Container, C4Component); строгую диаграмму с интерфейсами — PlantUML.

```text title="PlantUML component: элементы"
skinparam componentStyle uml2   UML-нотация компонентов
component "Имя" as C            компонент
interface "API" as I            интерфейс
C -- I                          C предоставляет I («леденец»)
D ..> I : использует            D требует I
package "Система" { ... }       группировка
port p / portin / portout       порты на границе компонента
[Имя]                           короткая запись компонента
```

## В визуальном редакторе

**draw.io:** в библиотеке UML есть компонент, интерфейс («леденец») и требуемый интерфейс («гнездо»). Если нужна строгая модель с повторным использованием элементов на разных диаграммах — Enterprise Architect и аналоги.

Что изменилось:

- **Появились интерфейсы:** видно, что провижининг зависит от API ядра и REST адаптера АБС, а не «от IdM вообще».
- **Убран сервер с IP-адресом** — это физика, ей место на диаграмме развёртывания.
- **Зависимости подписаны:** зачем провижинингу каждый интерфейс.
- **Убрана обратная стрелка АБС → IdM**, которой в реальности нет: адаптер не вызывает IdM.

## Упражнение

<Exercise title="подключение CRM">

Упражнение 5 из <a href="/case/cheatsheet/#10-вопросы-для-самопроверки-и-упражнения">шпаргалки кейса</a>: банк подключает к IdM новую систему — CRM. Нарисуйте диаграмму компонентов: где появится новый компонент, какой интерфейс он реализует и что вызывает. Подсказка: NFR-10 требует подключать типовые коннекторы настройкой, без доработки ядра.

<Fragment slot="solution">

<PlantUmlDiagram file="howto/component-crm-solution.puml" source="site" title="Подключение CRM — одно из возможных решений" />

- **Новый компонент — только «Коннектор CRM»**, реализующий общий **интерфейс коннектора** (create / enable / grant / revoke). Ядро и сервис провижининга не меняются — так выполняется NFR-10.
- **Коннектор вызывает API CRM**; формат и ошибки — в отдельном контракте.
- Что ещё изменится вне диаграммы: строка в карте интеграций, колонка в маппинге, полномочия CRM в каталоге, тест-кейсы — и проверка по матрице трассировки.

</Fragment>

</Exercise>
