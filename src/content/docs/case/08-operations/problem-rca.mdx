## 1. Хронология причин

| Когда             | Что произошло                                                                                                                                                     |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Май 2027          | Нагрузочные испытания АБС: пиковые потоки от разных систем замедляют закрытие дня. Команда АБС решает ограничить частоту запросов через адаптер                   |
| 11.06.2027        | Релиз адаптера 1.4.0 с ограничением 30 запросов в минуту на клиента и блокировкой на 120 секунд при превышении. Контракт не изменён, потребители не предупреждены |
| 14.06.2027, 09:00 | Плановое создание учётных записей для 67 сотрудников (волна набора операционистов): 67 запросов, 37 отклонены                                                     |
| 09:01             | Повтор 37 запросов попадает в блокировку клиента — все отклонены                                                                                                  |
| 09:06             | Повтор снова приходит одновременно: 37 запросов при лимите 30                                                                                                     |
| 09:06             | 7 задач исчерпали 3 попытки → MANUAL                                                                                                                              |

## 2. Пять «почему»

1. **Почему 7 учётных записей не созданы?** Три попытки создания получили 503.
2. **Почему 503?** Адаптер отклонял запросы сверх 30 в минуту.
3. **Почему IdM превысила лимит?** Создание всех учётных записей запланировано на 09:00, а повторы через фиксированные 1 и 5 минут приходят одновременно — пик повторяется; повтор через минуту к тому же короче блокировки в 120 секунд.
4. **Почему IdM не учла ограничение?** О нём не знала: ограничение не описано в контракте, а для превышения лимита использован код 503, который по контракту означает недоступность АБС.
5. **Почему изменение не согласовали?** Для адаптера нет обязательного процесса изменения контракта: команда АБС считала ограничение внутренней мерой защиты, а не изменением интерфейса.

## 3. Корневые причины

| № | Причина                                                                                                                                    | Тип            |
| - | ------------------------------------------------------------------------------------------------------------------------------------------ | -------------- |
| 1 | Изменение поведения интерфейса без изменения контракта и уведомления потребителей                                                          | Процесс        |
| 2 | Нет НФТ на пропускную способность адаптера и на поведение IdM при ограничении частоты (429, `Retry-After`, разнесение запросов во времени) | Требования     |
| 3 | Политика повторов с фиксированными интервалами синхронизирует повторы всех задач                                                           | Проектирование |
| 4 | Нет сигнала о росте ручных задач — массовый сбой выглядел как набор единичных задач у администраторов                                      | Мониторинг     |
| 5 | Нагрузочный тест [TC-19](/case/07-testing/test-cases/#tc-19) проверял обработку событий, но не поток в целевые системы                     | Тестирование   |
