## 1. Уровни модели данных

| Уровень        | Что показывает                                                        | Кто делает       | Этот документ            |
| -------------- | --------------------------------------------------------------------- | ---------------- | ------------------------ |
| Концептуальная | Основные сущности и связи бизнеса, без атрибутов                      | БА / СА          | Раздел 2                 |
| Логическая     | Сущности, атрибуты, ключи, связи, кардинальности; без привязки к СУБД | СА               | Диаграмма и раздел 3     |
| Физическая     | Таблицы, типы СУБД, индексы, партиционирование                        | Разработка / DBA | Нет — делает команда IdM |

## 2. Ключевые решения модели

- **Идентичность ≠ трудоустройство ≠ учётная запись.** Одно физическое лицо (identity) может иметь несколько трудоустройств (совместительство, повторный приём) и много учётных записей (по одной на систему). Если смешать эти сущности, повторный приём и совместительство сломают модель.
- **Роли назначаются на трудоустройство, а не на человека.** При внутреннем совместительстве роли двух должностей не смешиваются, а при завершении одного трудоустройства (волна 2) понятно, какие права отзывать.
- **У каждого выданного полномочия есть основание** (`account_entitlement.basis_type` + `basis_id`): роль, заявка или исключение SoD. Это реализация цели [G-03](/case/00-project/project-charter/#g-03).
- **Идемпотентность хранится в данных.** `hr_event_inbox.event_id` защищает от повторной обработки событий, `provisioning_task.task_id` передаётся в целевые системы как ключ идемпотентности.
- **Журнал аудита — отдельное хранилище** (`audit_event`, append-only), поэтому на ER-диаграмме не показан. Атрибуты: `audit_id`, `occurred_at`, `actor_type` (USER, SYSTEM), `actor_id`, `action`, `object_type`, `object_id`, `basis`, `result`, `correlation_id`.

## 3. Сущности

| Сущность                               | Назначение                        | Ключевые правила                                                                                                        |
| -------------------------------------- | --------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| identity                               | Физическое лицо                   | `person_id` уникален; создаётся по первому событию HIRE                                                                 |
| employment                             | Трудоустройство                   | `hr_employment_id` уникален; у идентичности может быть несколько                                                        |
| org_unit                               | Подразделение                     | Источник `timezone` ([FR-08](/case/02-requirements/functional-requirements/#fr-08)) и `abs_branch_code` (маппинг в АБС) |
| position                               | Должность                         | Справочник из HRMS                                                                                                      |
| hr_event_inbox                         | Обработанные события              | Повторный `event_id` не обрабатывается ([FR-03](/case/02-requirements/functional-requirements/#fr-03))                  |
| target_system                          | Целевая система                   | `connector_type = MANUAL` → задача в ServiceDesk ([FR-17](/case/02-requirements/functional-requirements/#fr-17))        |
| entitlement                            | Полномочие                        | `is_critical` определяет участие ИБ в согласовании                                                                      |
| business_role, role_entitlement        | Бизнес-роли и их состав           | Роль [ROLE-00](/case/02-requirements/role-model/#role-00) имеет `is_birthright = true`                                  |
| assignment_rule                        | Правило назначения                | `null` в условии означает «любой»                                                                                       |
| sod_rule                               | SoD-правило                       | Проверяется перед выдачей любого полномочия                                                                             |
| account                                | Учётная запись                    | Пара (`identity_id`, `system_code`) уникальна в волне 1                                                                 |
| role_assignment                        | Назначенная роль                  | `source` = RULE или REQUEST                                                                                             |
| account_entitlement                    | Выданное полномочие               | Обязательное основание                                                                                                  |
| provisioning_task                      | Операция в целевой системе        | `task_id` = ключ идемпотентности; статусы — [`04_state-models.md`](/case/03-architecture/state-models/)                 |
| reserved_login                         | Резерв логинов уволенных          | Переиспользуется только тем же `person_id`                                                                              |
| access_request, request_item, approval | Заявка, её позиции и согласования | Согласование — на уровне позиции, т.к. у разных полномочий разные владельцы                                             |
