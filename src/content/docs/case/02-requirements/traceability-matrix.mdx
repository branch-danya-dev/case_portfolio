Версия 1.0 · Автор: Системный аналитик · Обновляется при каждом изменении требований

Трассировка связывает цель проекта с тестом, который доказывает её достижение:

```
Цель (G) → Бизнес-требование (BR) → Функциональное требование (FR) → Use case (UC)
        → Интеграция / сценарий (INT, SEQ) → Тест (TC)
```

Зачем это нужно на практике:

- **Анализ влияния.** Заказчик хочет поменять [BR-04](/case/01-business/business-requirements/#br-04) — по матрице видно, какие FR, интеграции и тесты затронуты.
- **Поиск «сирот».** FR без BR — лишняя работа или пропуск в БТ. FR без теста — никто не проверит.
- **Приёмка.** На приёмке показывают, что каждое M-требование покрыто пройденным тестом.
