## 2. Пользовательские истории (пример нарезки)

Формат: «Как \<роль>, я хочу \<действие>, чтобы \<ценность>». Критерии приёмки — в формате Gherkin (Дано / Когда / Тогда).

### <span id="us-01" class="case-anchor" />US-01. Автоматический запуск по приказу (EPIC-01, FR-01, FR-03)

Как HR-специалист, я хочу, чтобы подготовка доступов запускалась после проведения приказа, чтобы не уведомлять руководителя вручную.

```gherkin
Сценарий: Новое событие о приёме
  Дано в HRMS проведён приказ о приёме сотрудника с personId "P-100500"
  Когда IdM получает событие HIRE с eventId "e-1"
  Тогда в IdM создаётся идентичность в статусе PRE_HIRE
  И в журнале аудита есть запись с основанием "eventId e-1"

Сценарий: Повторная доставка того же события
  Дано событие с eventId "e-1" уже обработано
  Когда IdM повторно получает событие с eventId "e-1"
  Тогда новых идентичностей и задач провижининга не создаётся
  И событие подтверждается в шине
```

### <span id="us-02" class="case-anchor" />US-02. Уникальный логин (EPIC-02, FR-06)

Как администратор AD, я хочу, чтобы логин генерировался по единому правилу, чтобы не разбирать коллизии вручную.

```gherkin
Сценарий: Коллизия логина
  Дано в AD существует учётная запись "ivanov.ap"
  Когда принимается сотрудник "Иванов Андрей Павлович"
  Тогда ему назначается логин "ivanov.ap2"

Сценарий: Длинная фамилия
  Когда принимается сотрудник "Константинопольский Ярослав Юрьевич"
  Тогда ему назначается логин "konstantinopolski.ii" длиной 20 символов
```

## 3. Definition of Ready (история готова к взятию в спринт)

- Есть формулировка «Как … я хочу … чтобы …» и ссылка на ФТ.
- Есть критерии приёмки, проверяемые тестом.
- Описаны затронутые интеграции и контракты (ссылки на OpenAPI / AsyncAPI).
- Зависимости от других команд (HRMS, АБС) согласованы.
- Оценка команды есть, история помещается в спринт.

## 4. Definition of Done (история завершена)

- Код прошёл ревью, автотесты зелёные.
- Критерии приёмки проверены QA на тестовом стенде.
- Обновлена документация (ФТ, контракт API, статусная модель — если затронуты).
- Действия пишутся в журнал аудита.
- Метрики и алерты добавлены (для историй с интеграциями).
