Версия 1.0 · Статус: Согласован · Автор: QA (при участии СА) · Утверждает: Бизнес-заказчик, CISO

ПМИ — документ, по которому заказчик принимает систему. Он отвечает на вопросы: **что проверяем, где, как, кто участвует и по какому критерию считаем испытания успешными**. Структура близка к принятой в стандартах серии ГОСТ 34, но упрощена.

## 1. Объект испытаний

Модернизированная IdM с подключениями [INT-01](/case/04-integrations/integration-map/#int-01) … [INT-09](/case/04-integrations/integration-map/#int-09) и адаптер АБС версии 1.0.

## 2. Цель испытаний

Подтвердить, что система выполняет требования [FR-01](/case/02-requirements/functional-requirements/#fr-01) … [FR-23](/case/02-requirements/functional-requirements/#fr-23) и [NFR-01](/case/02-requirements/non-functional-requirements/#nfr-01) … [NFR-13](/case/02-requirements/non-functional-requirements/#nfr-13) и готова к пилотной эксплуатации.

## 4. Условия проведения

- Тестовый контур: HRMS (тестовая база), Kafka (тестовый кластер), тестовый домен AD, тестовый Exchange, тестовая АБС с адаптером, тестовый ServiceDesk, заглушка SMS-шлюза.
- Тестовые данные: 50 синтетических сотрудников, включая длинные и двойные фамилии, однофамильцев, повторно принятых, совместителей, подразделения в 4 часовых поясах.
- Время на стенде управляемое: для проверки активации в 07:00 используется сдвиг системного времени планировщика.

## 5. Участники

| Роль                                | Участие                                                    |
| ----------------------------------- | ---------------------------------------------------------- |
| QA                                  | Выполнение тестов, протокол                                |
| СА                                  | Разбор спорных результатов: дефект или неверное требование |
| Представители HR, руководителей, ИБ | Приёмочные сценарии                                        |
| Администраторы AD, АБС              | Проверка результатов в целевых системах                    |

## 6. Критерии успешности

- Все тесты приоритета M пройдены.
- Нет открытых дефектов критичности 1 (блокирующий) и 2 (критичный).
- Дефекты критичности 3–4 имеют план исправления до тиражирования.
- [NFR-01](/case/02-requirements/non-functional-requirements/#nfr-01) подтверждён нагрузочным тестом.

## 7. Отчётность

Протокол испытаний с результатом по каждому тесту; перечень дефектов; заключение о готовности к пилоту, подписанное заказчиком и CISO.
