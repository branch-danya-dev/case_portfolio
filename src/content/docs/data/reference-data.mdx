<Brief>

**НСИ** (нормативно-справочная информация) — справочники и классификаторы, общие для многих систем: подразделения, должности, валюты, продукты, коды операций.
Для каждого справочника нужно определить **мастер-систему**, **владельца**, **как изменения доходят до потребителей** и **что делать, если значения нет**.
Справочники — частая причина сбоев интеграций: у одного объекта в разных системах разные коды. Без таблицы соответствия интеграция «работает» только на тестовых данных.

</Brief>

## Когда применять

| Применять | Не нужно |
|---|---|
| Интеграция систем с разными кодами одного объекта | Внутренний перечень из 3 значений, который не меняется (статус) — хватит enum |
| Поведение системы зависит от справочных данных (роли, тарифы, правила) | Отдельная MDM-платформа для маленького проекта |
| Миграция: старые и новые коды | — |
| Требования к отчётности с группировкой по справочникам | — |

## Как делать

<Steps>

1. **Перечислите справочники**, от которых зависит решение: что из них читается, где они живут.

2. **Для каждого — мастер-система** (источник правды) и **владелец** (кто отвечает за корректность).

3. **Таблица соответствия** кодов между системами: код в источнике → код в приёмнике.

4. **Как доставляются изменения:** событие, периодическая выгрузка, ручное ведение. С какой задержкой.

5. **Версионирование:** даты действия (`valid_from`, `valid_to`), история; что происходит с данными, ссылающимися на закрытое значение.

6. **Поведение при отсутствии значения:** ошибка, значение по умолчанию, задача ответственному.

7. **Контроль качества:** регулярная проверка полноты — например, запрос «подразделения без кода АБС».

</Steps>

```markdown title="Паспорт справочника (шаблон)"
| Версионирование | <даты действия, история> |
| Нет значения у потребителя | <ошибка / значение по умолчанию / задача> |
| Контроль качества | <проверки и их периодичность> |
```

| Понятие | Смысл |
|---|---|
| НСИ | Справочники и классификаторы, общие для систем |
| Мастер-система | Где справочник ведётся и откуда берётся правда |
| Таблица соответствия (маппинг кодов) | Код объекта в системе A → код в системе B |
| MDM (Master Data Management) | Управление основными данными (клиенты, контрагенты, продукты) так, чтобы во всех системах была согласованная версия |
| Золотая запись (golden record) | Эталонная запись об объекте, собранная из нескольких источников по правилам приоритета |
| Даты действия | Период, когда значение актуально; позволяют хранить историю |

## Пример из кейса IDM-JOINER

**Справочник подразделений** — <CaseRef href="/case/04-integrations/data-mapping/" id="Маппинг">маппинг данных кейса</CaseRef>, раздел 2:

| `org_unit_code` | Название | `org_unit_type` | `timezone` | OU в AD | `abs_branch_code` |
|---|---|---|---|---|---|
| 0001 | Головной офис, ДИТ | `IT_DEPT` | Europe/Moscow | `OU=IT,OU=HQ,…` | 000 |
| 1601 | Доп. офис «Екатеринбург-Центр» | `RETAIL_OFFICE` | Asia/Yekaterinburg | `OU=EKB,OU=Branches,…` | 066 |
| 2501 | Доп. офис «Владивосток» | `RETAIL_OFFICE` | Asia/Vladivostok | `OU=VVO,OU=Branches,…` | 025 |

Что показывает кейс:

- **Один справочник обслуживает несколько систем:** часовой пояс — для активации в 07:00 (FR-08), OU — для AD, `abs_branch_code` — для АБС, тип подразделения — для правил назначения ролей.
- **Мастер подразделений — HRMS**, но атрибуты для AD и АБС HRMS не знает. Их ведёт **команда IdM** (владелец справочника по <CaseRef href="/case/06-rollout/migration-strategy/" id="Миграция">стратегии миграции</CaseRef>).
- **Поведение при отсутствии значения определено:** нет `abs_branch_code` → бизнес-ошибка → задача в ServiceDesk.
- **Ролевая модель — тоже справочные данные**, причём самые долгие по согласованию: <CaseRef href="/case/02-requirements/role-model/" id="Роли">ролевая модель</CaseRef> утверждается ИБ, правила назначения имеют даты действия.

Проверка полноты справочника на учебной БД — запрос из страницы [SELECT и фильтры](/data/sql-select/#пример-из-кейса-idm-joiner): новый офис «Находка» без кода АБС найден до того, как туда вышел сотрудник.

## Типичные ошибки

| Ошибка | Чем плохо | Как правильно |
|---|---|---|
| «Это просто справочник, потом» | Интеграции падают на реальных данных; согласование затягивает сроки | Справочники — требования с владельцем и сроком |
| Нет владельца | Расхождения никто не исправляет | Владелец в паспорте справочника |
| Нет таблицы соответствия кодов | Интеграция работает только на тестовых данных | Маппинг кодов как отдельный артефакт |
| Нет правила для отсутствующего значения | Сбои и «тихие» ошибки | Явное поведение: ошибка, значение по умолчанию, задача |
| Удалять закрытые значения | Исторические данные ссылаются в никуда | Даты действия, мягкое закрытие |
| Копировать справочник вручную в каждую систему | Расхождения со временем | Мастер-система и автоматическая доставка |
