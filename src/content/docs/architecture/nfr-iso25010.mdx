<Brief>

**НФТ** описывают, **насколько хорошо** работает система: скорость, ёмкость, надёжность, безопасность, сопровождаемость. Главное правило — **измеримость**: метрика, значение, условия, способ проверки.
**ISO/IEC 25010** — модель качества продукта; её характеристики удобно использовать как **чек-лист**, чтобы не забыть категорию НФТ.
НФТ часто влияют на архитектуру сильнее, чем ФТ, поэтому их согласует архитектор.

</Brief>

## Когда применять

| Применять | Не нужно |
|---|---|
| Любой проект, который пойдёт в эксплуатацию | Переписывать стандарт целиком в требования |
| Архитектурные решения: НФТ — главный вход | Формулировать НФТ «на всякий случай» без источника |
| Приёмка: нагрузочное тестирование, учения DR, проверки ИБ | — |
| Договоры и SLA с подрядчиками и смежными командами | — |

## Как делать

<Steps>

1. **Пройдите по чек-листу характеристик** (таблица ниже): для каждой — есть ли требования у этой системы.

2. **Найдите источники:** цели проекта, стандарты ИТ и ИБ компании, регуляторика, договоры, объёмы из AS-IS.

3. **Сформулируйте измеримо:** метрика + значение + условия + способ проверки.

4. **Проверьте реализуемость и цену** с архитектором: каждая «девятка» доступности дорожает многократно.

5. **Свяжите НФТ с проверкой:** нагрузочный тест, учения DR, сканирование, юзабилити-тест.

6. **Свяжите с архитектурой:** какие решения следуют из НФТ (кластер, асинхронность, кэш) — в ADR.

</Steps>

|----|-----------|------------|---------------|----------|

|---|---|

| Система должна быть безопасной | Журнал аудита хранится 5 лет, защищён от изменения; доступ на чтение — только ИБ и аудит |
| Удобный интерфейс | Руководитель без обучения создаёт заявку не более чем за 3 минуты (юзабилити-тест, 5 человек) |

| Доступность | Простой в год | В месяц (30 дней) | В неделю |
|---|---|---|---|
| 99% | ≈ 3,65 дня | ≈ 7,2 ч | ≈ 1,7 ч |
| 99,5% | ≈ 43,8 ч | ≈ 3,6 ч | ≈ 50 мин |
| 99,9% | ≈ 8,76 ч | ≈ 43,2 мин | ≈ 10 мин |
| 99,95% | ≈ 4,38 ч | ≈ 21,6 мин | ≈ 5 мин |
| 99,99% | ≈ 52,6 мин | ≈ 4,3 мин | ≈ 1 мин |

| Термин | Смысл |
|---|---|
| RTO | Recovery Time Objective — за какое время восстановиться |
| RPO | Recovery Point Objective — сколько данных (по времени) допустимо потерять |
| MTBF / MTTR | Среднее время между отказами / среднее время восстановления |
| SLA / SLO / SLI | Соглашение об уровне сервиса / целевое значение / измеряемый показатель |

Договоритесь, что считается недоступностью (нет ответа, ошибки, ответ дольше N секунд), за какой период считается процент и входят ли плановые работы.

## Пример из кейса IDM-JOINER

<CaseRef href="/case/02-requirements/non-functional-requirements/" id="НФТ">НФТ кейса</CaseRef> разложены по категориям ISO/IEC 25010, у каждого — способ проверки и источник:

| НФТ | Что показывает |
|---|---|
| <CaseRef href="/case/02-requirements/non-functional-requirements/#nfr-01" id="NFR-01">NFR-01</CaseRef> | Производительность: 95% событий — до 5 минут, с метрикой для проверки |
| <CaseRef href="/case/02-requirements/non-functional-requirements/#nfr-03" id="NFR-03">NFR-03</CaseRef> | Ёмкость: штатно 20, пиково 300 событий в день — источник в уставе |
| <CaseRef href="/case/02-requirements/non-functional-requirements/#nfr-04" id="NFR-04">NFR-04</CaseRef> | Надёжность: 99,5% **круглосуточно**, потому что 07:00 во Владивостоке — 00:00 по Москве; RTO 4 ч, RPO 15 мин |
| <CaseRef href="/case/02-requirements/non-functional-requirements/#nfr-05" id="NFR-05">NFR-05</CaseRef> | Надёжность: at-least-once, потеря событий недопустима → идемпотентность (FR-03) |
| <CaseRef href="/case/02-requirements/non-functional-requirements/#nfr-10" id="NFR-10">NFR-10</CaseRef> | Сопровождаемость: новый типовой коннектор — настройкой, без доработки ядра |
| <CaseRef href="/case/02-requirements/non-functional-requirements/#nfr-12" id="NFR-12">NFR-12</CaseRef> | Удобство: заявка за 3 минуты без обучения, проверка на пилоте |

Вывод документа: NFR-05 потребовал идемпотентности, NFR-04 — кластерного развёртывания. Поэтому НФТ утверждает архитектор.

## Типичные ошибки

| Ошибка | Чем плохо | Как правильно |
|---|---|---|
| Неизмеримые формулировки | Нельзя спроектировать и принять | Метрика, значение, условия, проверка |
| «99,99%» без обоснования | Дорогая архитектура без бизнес-необходимости | Доступность от реальной потребности и цены простоя |
| Нет условий нагрузки | «2 секунды» при 1 пользователе и при 1 000 — разные системы | Объём, пики, рост |
| Забыты категории (сопровождаемость, наблюдаемость) | Система работает, но её нельзя развивать и мониторить | Чек-лист ISO 25010 + эксплуатация |
| НФТ без способа проверки | Не проверяется на приёмке | Тест, мониторинг, учения |
| НФТ не связаны с архитектурой | Требования есть, а решения под них нет | ADR со ссылками на НФТ |
