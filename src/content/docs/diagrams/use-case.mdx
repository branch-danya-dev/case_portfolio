<Brief>

**Диаграмма вариантов использования** (use case diagram) — обзор: **кто** (акторы) и **зачем** (прецеденты) пользуется системой, где её **граница**.
Это оглавление, а не спецификация: детали — основной поток, альтернативы, исключения — описываются текстом, см. [Use cases](/requirements/use-cases/).
Связи между прецедентами: **include** — всегда включает, **extend** — расширяет при условии.

</Brief>

## Когда применять

| Применять | Не нужно |
|---|---|
| Показать заказчику и команде, кто и для чего использует систему | Описать поведение подробно → текстовая спецификация |
| Найти забытых акторов (системы, таймеры, аудит) | Процесс с передачей работы между людьми → BPMN |
| Определить скоуп: что внутри границы, что снаружи | Алгоритм → activity |
| Оглавление для набора спецификаций | — |

## Как делать

<Steps>

1. **Нарисуйте границу системы** — прямоугольник с названием.

2. **Найдите акторов:** люди в разных ролях, внешние системы, время (таймер). Акторы — **снаружи** границы.

3. **Для каждого актора — его цели** с системой: прецеденты «глагол + объект» внутри границы.

4. **Соедините акторов с прецедентами** — ассоциация (линия).

5. **Общие части — include**, условные расширения — **extend**. Не злоупотребляйте: это не дерево функций.

6. **Проверьте:** каждый прецедент даёт результат, ценный для актора; нет «кнопок»; нет внутренних компонентов в роли акторов.

</Steps>

## Нотация

| Элемент | Вид | Правило |
|---|---|---|
| Актор (actor) | Человечек | Роль, внешняя по отношению к системе; может быть системой или таймером |
| Прецедент (use case) | Овал | Цель актора: «глагол + объект» |
| Граница системы | Прямоугольник | Всё, что внутри, — делает система |
| Ассоциация | Линия | Актор участвует в прецеденте |
| `<<include>>` | Пунктир со стрелкой **от базового** к включаемому | Базовый **всегда** выполняет включаемый |
| `<<extend>>` | Пунктир со стрелкой **от расширения** к базовому | Расширение выполняется **при условии** |
| Обобщение | Линия с пустым треугольником к родителю | Наследник умеет всё, что родитель, и больше |

## Типичные ошибки

| Ошибка | Чем плохо | Как правильно |
|---|---|---|
| Прецедент = кнопка или экран («Нажать Сохранить») | Сотни овалов, цели не видны | Цель актора |
| Дерево include (функциональная декомпозиция) | Диаграмма превращается в схему модулей | include только для реально общих частей |
| Перепутано направление include / extend | Смысл меняется на противоположный | include — от базового; extend — к базовому |
| Внутренний компонент как актор | Нарушена граница системы | Акторы только внешние |
| Только диаграмма без спецификаций | Альтернативы и ошибки не описаны | Текст для значимых прецедентов |
