<Brief>

Аналитику нужны пять групп инструментов: **трекер и вики** (где живут задачи и требования), **моделирование** (диаграммы), **API-клиенты** (проверить интеграцию), **клиент БД** (посмотреть данные) и **просмотр брокера** (найти сообщение). Шестая группа — **инфраструктура проекта** (Docker, Kubernetes, CI/CD, логи, метрики, Keycloak, Vault): её не настраивают, но читают. Что знать на каком уровне — в [технологическом стеке по уровням](/software/stack/).
Инструмент выбирает не аналитик, а компания: важно понимать **класс задачи** и уметь быстро перейти на аналог. На собеседовании ценится не список программ, а ответ «чем и как я проверял».
Каждая карточка отвечает на вопросы: **что это, когда применять, зачем аналитику, чем заменить**.

</Brief>

## Группы

| Группа | Задачи аналитика | Типичный набор |
|---|---|---|
| [Требования, задачи, документация](/software/tasks-docs/) | Бэклог, истории, страницы требований, трассировка, согласования | Jira + Confluence; VS Code + Git для docs-as-code |
| [Моделирование](/software/modeling/) | Процессы, UML, C4, ER, макеты | draw.io, Camunda Modeler, PlantUML / Mermaid |
| [API](/software/api/) | Читать и писать контракты, вызывать методы, заглушки | Swagger Editor, Postman или Bruno, curl |
| [Данные](/software/data/) | Исследовать БД, писать SQL, проверять результат теста | DBeaver, клиент «родной» СУБД |
| [Брокеры сообщений](/software/brokers/) | Найти событие, проверить формат, отставание потребителя | Kafka UI или AKHQ, kcat, RabbitMQ Management |
| [Инфраструктура и эксплуатация](/software/infra/) | Найти операцию в логах, проверить релиз по метрикам, понять среды и доступы | Kibana, Grafana, GitLab CI, Docker, Kubernetes, Keycloak, Vault |

## Как выбирать

| Ситуация | На что смотреть |
|---|---|
| Банк, закрытый контур | Работает ли без облака и учётной записи; можно ли развернуть у себя; одобрено ли ИБ |
| Документация живёт рядом с кодом | Текстовые форматы: Markdown, PlantUML, Mermaid, OpenAPI; ревью через merge request |
| Диаграмму будут править многие | Стандартный формат файла (.bpmn, .drawio, .puml) вместо картинки |
| Конфиденциальные данные | Никаких онлайн-форматтеров и онлайн-редакторов «на минутку» — только локальные инструменты |
| Нужна трассировка | Связи задач в трекере или репозиторий моделей, а не ручная таблица |

<Check id="soft-01">
Доступность и условия лицензирования зарубежных продуктов (Atlassian Jira и Confluence, Postman, Figma и др.) для российских компаний меняются. Перед рекомендацией в конкретной ситуации — сверить с сайтом производителя и политикой компании; перечень российских аналогов тоже стоит сверить с реестром отечественного ПО.
</Check>

## Типичные ошибки

| Ошибка | Чем плохо | Как правильно |
|---|---|---|
| Учить кнопки, а не задачи | При смене компании знания обесцениваются | Понимать класс задачи: «проверить контракт», «найти сообщение» |
| Вставлять боевые данные в онлайн-сервисы | Утечка ПДн и банковской тайны | Только локальные и одобренные ИБ инструменты |
| Диаграмма — только PNG | Её никто не может поправить | Хранить исходник (.drawio, .bpmn, .puml) рядом |
| Требования в трекере без вики | Описание системы теряется в закрытых задачах | Долгоживущее — в вики, единицы работы — в трекере |
| Не проверять интеграцию самому | Спорные дефекты разбираются «на слово» | Postman / curl / просмотр топика — базовый навык |
