<Brief>

Асинхронную интеграцию нельзя проверить «запросом»: нужно **найти сообщение** в топике или очереди, сверить его с контрактом и посмотреть, **читает ли его потребитель**.
Для Kafka — веб-интерфейсы (Kafka UI, AKHQ), десктопный клиент (Offset Explorer) или командная строка (kcat); для RabbitMQ — встроенный Management UI.
Главные вопросы при разборе инцидента: дошло ли событие, в каком виде, нет ли его в DLQ, какое отставание у группы потребителей.

</Brief>

## Как выбрать

| Нужно | Инструмент |
|---|---|
| Посмотреть сообщения и группы потребителей в браузере | Kafka UI, AKHQ |
| Нет веб-интерфейса, есть доступ к брокеру | Offset Explorer, kcat |
| Отправить тестовое сообщение из терминала | kcat |
| RabbitMQ: очереди, привязки, тестовая публикация | RabbitMQ Management UI |

## Пример из кейса IDM-JOINER

По <CaseRef href="/case/04-integrations/api-hr-events/" id="AsyncAPI">контракту кадровых событий</CaseRef> события приходят в топик `hr.employee.events.v1`, некорректные IdM перекладывает в `hr.employee.events.v1.dlq`. Разбор TC-03 («событие без обязательного поля») в Kafka UI: найти событие по `eventId` в основном топике, убедиться, что оно появилось в DLQ, и сверить, какого поля не хватает, со схемой из контракта.

## Типичные ошибки

| Ошибка | Чем плохо | Как правильно |
|---|---|---|
| Искать «пропавшее» событие только в основном топике | Не видно, что оно ушло в DLQ | Проверять и DLQ |
| Отправлять тестовые сообщения в общий топик стенда | Ломаются тесты других команд | Согласовать, использовать отдельный топик или ключ |
| Читать сообщения своей группой потребителей сервиса | Сдвигаются смещения боевого потребителя | Просмотр без коммита смещений или отдельная группа |
| Не смотреть отставание потребителя | Задержки обработки замечают по жалобам | Lag группы потребителей — первый показатель |
