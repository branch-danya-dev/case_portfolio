Справочник для проектирования и ревью API: какой код вернуть в ситуации, чем 401 отличается от 403, а 409 от 422, какие методы идемпотентны и можно ли повторить запрос после ошибки. Примеры взяты из контрактов кейса — API IdM и адаптера АБС. Ссылка вида `/tools/http-reference/#409` открывает карточку кода.

<HttpReference client:load />

Коды и методы — по RFC 9110 (HTTP Semantics), PATCH — RFC 5789, 428 и 429 — RFC 6585. Формат тела ошибки — [Problem Details (RFC 9457)](/integrations/rest-design/). Выбор между 400 и 422 для бизнес-ошибок — соглашение конкретного API: важно выбрать одно и описать его в контракте.
