Главный цикл работы с API: **отправил запрос → получил неожиданный ответ → нашёл причину → исправил**. Пишите запрос сами — в виде curl, сырого HTTP или формой, — и смотрите, что на самом деле ушло и что вернулось. На вкладке **«Задания»** — 14 сломанных запросов: каждый нужно починить, а засчитывается то, что реально пришло на сервер. Вкладка **«Контракт»** — цепочка contract-first: описать API в OpenAPI → проверить → посмотреть документацию → включить мок → отправить запрос.

<ApiLab client:only="react" />

**Как это устроено.** Учебный API работает прямо на странице: запросы не уходят в сеть, их обрабатывает встроенный сервер с настоящей логикой — токены и права, проверка формата и данных, идемпотентность, ограничение частоты, условные запросы с ETag, асинхронные операции. Ошибки — в формате Problem Details ([RFC 9457](/integrations/rest-design/)). Что значит каждый код и когда его возвращать — в [справочнике HTTP](/tools/http-reference/); прочитать и проверить чужой контракт — в [просмотрщике OpenAPI](/tools/openapi-viewer/). Решённые задания и контракт сохраняются только в этом браузере.
