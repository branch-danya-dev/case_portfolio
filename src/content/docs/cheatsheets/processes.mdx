## BPMN: элементы

| Элемент | Вид | Правило |
|---|---|---|
| Старт / промежуточное / конец | Тонкий / двойной / жирный круг | Событие = состояние: «Заявка подана» |
| Таймер, сообщение, ошибка | Часы, конверт, молния | Закрашенный маркер — бросающее |
| Граничное событие | Круг на границе задачи | Сплошное — прерывает, пунктир — нет |
| Задача | Скруглённый прямоугольник | «Глагол + объект» |
| Типы задач | Человек / шестерёнка / рука / конверт | User · service · manual · send/receive |
| Подпроцесс / call activity | «+» / жирная рамка | Группа шагов / переиспользуемый процесс |
| Пул / дорожка | Прямоугольник / полоса | Участник / роль внутри участника |
| Поток операций | Сплошная стрелка | Только внутри пула |
| Поток сообщений | Пунктир, кружок, пустая стрелка | Только между пулами |
| Аннотация, объект данных, хранилище | Скобка, лист, цилиндр | Токен по ним не ходит |

</section>

## Шлюзы

| Шлюз | Ветвление | Слияние |
|---|---|---|
| XOR × | Ровно одна ветка | Не ждёт |
| AND + | Все ветки | Ждёт все |
| OR ○ | Одна или несколько | Ждёт активированные |
| По событию ⬠ | Первое наступившее событие | — |

Шлюз — **вопрос**, ветки — **ответы**. Слияние — тем же типом. **Токен:** AND размножает, на слиянии ждёт все; две ветки прямо в задачу = задача **дважды**.

</section>

## BPMN: как и ошибки

Границы (старт / результат) → участники (пулы, дорожки) → счастливый путь → развилки → ожидания и исключения → **прогон токена** → детализация (≤ 20–25 задач, иначе подпроцессы) → аннотации P-…, BRL-….

**Ошибки:** задача без глагола · шлюз без вопроса · поток операций между пулами · слияние параллельных веток без AND · нет конечного события · шаг = клик · AS-IS и TO-BE на одной схеме · AS-IS по регламенту.

</section>

## AS-IS и TO-BE

**AS-IS** — как **на самом деле**: источники · участники · шаги с длительностью · проблемы P-… **с цифрами** · что работает хорошо.

**TO-BE** — принципы · шаги и исполнители · **бизнес-правила BRL-…** · исключения · ожидаемый эффект (те же метрики).

**Потери:** ожидание, лишние передачи, переделки, лишние согласования, ручной ввод, поиск информации.

**Главная ошибка TO-BE:** AS-IS, где «администратор» заменён на «система».

</section>

## Gap-анализ

| Аспект | AS-IS | TO-BE | Разрыв | Тип | Закрывает |
|---|---|---|---|---|---|

**Типы:** система → БТ, ФТ · данные → справочники, миграция · регламент → новая редакция, обучение · организация → роли, RACI, план внедрения.

**Кейс:** GAP-09 (приказы за 2 дня — регламент) и GAP-10 (владелец ролевой модели — организация) не закрываются системой, но без них цель G-01 недостижима.

**Fit-gap** — требования против возможностей готового продукта.
