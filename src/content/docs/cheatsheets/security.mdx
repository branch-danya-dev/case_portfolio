## Роль аналитика

ИБ задаёт **что**, аналитик встраивает в **каждый** артефакт: ролевая модель, ФТ, НФТ, контракт, модель данных, маппинг, тесты, мониторинг.
**Конфиденциальность** — видит только тот, кому можно · **целостность** — не изменено незаметно · **доступность** — работает, когда нужно.

</section>

<section>

## Доступ

| | Аутентификация | Авторизация |
|---|---|---|
| Вопрос | Кто ты? | Что можно? |
| Отказ | 401 | 403 |

**MFA** — два фактора разных типов: знание, владение, свойство.
**RBAC** — права через роли · **ABAC** — по атрибутам пользователя, объекта, контекста · на практике: роль даёт операцию, атрибуты ограничивают объекты.
**Проверка на уровне объекта** для каждой операции: «только подчинённые», «только назначенные мне». Иначе перебор id.
**Принципы:** минимальные привилегии · SoD · необходимость знать · запрет по умолчанию.
**Сервисная учётная запись:** владелец, минимальные права, своя на интеграцию и среду, люди не входят, секрет в хранилище со сроком замены.

</section>

<section>

## Токены и сессии

Токен доступа — минуты · токен обновления или сессия — часы · тайм-аут бездействия.
**JWT не отозвать** до `exp` → короткий срок, проверка блокировки при обновлении.
Описать: выход, блокировка, увольнение, смена пароля — **через сколько** доступ прекращается.
Секреты и сертификаты: срок, ответственный, замена **без простоя** (старый и новый принимаются одновременно).

</section>

<section>

## Данные

**In transit** — TLS, mTLS · **at rest** — диски, БД, бэкапы, отдельные поля · ключи **отдельно** от данных · пароли **хэшируют**, не шифруют.
**ПДн:** цель, минимизация, срок хранения, кому передаются, маскирование. Каждое поле — с обоснованием.
**Утечки:** логи, ошибки, тестовые среды, выгрузки, письма, URL. Логировать идентификаторы, токены и пароли — никогда.

</section>

<section>

## Журнал аудита

Кто · что · над чем · **основание** · результат (и отказы) · время · `correlationId`. Только добавление, годы хранения, читают ИБ и аудит, копия в SIEM. Не логи и без секретов.

</section>

<section>

## Угрозы

Схема потоков → **границы доверия** → STRIDE по каждой → мера и статус → требование и тест.

| | Угроза | Мера |
|---|---|---|
| S | Подмена | Аутентификация, mTLS |
| T | Изменение | Подпись, журнал только на добавление |
| R | Отказ от авторства | Аудит с основанием |
| I | Раскрытие | Проверка объекта, шифрование |
| D | Отказ в обслуживании | Лимиты, 429 |
| E | Повышение привилегий | Минимальные права, SoD |

**Лимиты:** кого, сколько за окно, 429 + `Retry-After`, строже для входа и кодов, в контракте. **Злоупотребления логикой** (самосогласование) находит аналитик, а не сканер.

</section>
