## Что чем рисовать

| Диаграмма | Mermaid | PlantUML | Иначе |
|---|---|---|---|
| Sequence, state, class, ER | да | да | — |
| Activity | flowchart | да (дорожки, fork) | — |
| Use case | нет | да | draw.io |
| C4 | экспериментально | да (`!include <C4/…>`) | Structurizr |
| BPMN | нет | нет | Camunda Modeler, bpmn.io, [BPMN-редактор](/tools/bpmn-editor/) |
| DFD | приближение flowchart | приближение | draw.io |

Стрелки: Mermaid `->>` синхронно, `-)` асинхронно, `-->>` ответ; PlantUML `->`, `->>`, `-->`.

</section>

## Sequence

```text title="Mermaid"
sequenceDiagram
  autonumber
  participant A as Сервис
  participant B as АБС
  A->>B: POST /users
  B-->>A: 201 Created
  A-)B: асинхронно
  alt успех
    B-->>A: 200
  else ошибка
    B-->>A: 503
  end
  loop 3 попытки
    A->>B: повтор
  end
  Note over A,B: Idempotency-Key
```

```text title="PlantUML"
@startuml
autonumber
participant "Сервис" as A
participant "АБС" as B
queue Kafka as K
A -> B : POST /users
B --> A : 201 Created
A ->> K : событие
alt успех
  B --> A : 200
else ошибка
  B --> A : 503
end
loop 3 попытки
  A -> B : повтор
end
note over A, B : Idempotency-Key
@enduml
```

## Activity / flowchart

```text title="Mermaid flowchart"
flowchart TD
  A([Начало]) --> B[Провести приказ]
  B --> C{Роль найдена?}
  C -- да --> D[Назначить роли]
  C -- нет --> E[Базовая роль]
  D & E --> F[(БД IdM)]
  subgraph IdM
    D
    E
  end
```

```text title="PlantUML activity"
@startuml
|HR|
start
:Провести приказ;
|IdM|
if (Роль найдена?) then (да)
  :Назначить роли;
else (нет)
  :Базовая роль;
endif
fork
  :AD;
fork again
  :АБС;
end fork
while (Есть ошибки?) is (да)
  :Повторить;
endwhile (нет)
stop
@enduml
```

## Class

```text title="Mermaid"
classDiagram
  class Account {
    +String login
    +block()
  }
  Identity "1" --> "*" Account : владеет
  Account <|-- AdAccount
  Identity *-- Employment
  Identity o-- Role
```

```text title="PlantUML"
@startuml
class Account {
  +login : String
  +block()
}
Identity "1" -- "*" Account : владеет
Account <|-- AdAccount
Identity *-- Employment
Identity o-- Role
@enduml
```

`<|--` наследование · `*--` композиция · `o--` агрегация.

## ER

```text title="Mermaid"
erDiagram
  IDENTITY ||--o{ ACCOUNT : "имеет"
  IDENTITY {
    int identity_id PK
    string person_id
  }
  ACCOUNT {
    int account_id PK
    int identity_id FK
    string login
  }
```

```text title="PlantUML"
@startuml
entity identity {
  * identity_id : int <<PK>>
  --
  * person_id : text
}
entity account {
  * account_id : int <<PK>>
  --
  * identity_id : int <<FK>>
  login : text
}
identity ||--o{ account
@enduml
```

Кардинальность: `||` ровно один · `|o` ноль или один · `}o` ноль или много · `}|` один или много.

## Use case (только PlantUML)

```text title="PlantUML"
@startuml
left to right direction
actor "Руководитель" as M
rectangle IdM {
  usecase "Запросить доступ" as UC1
  usecase "Проверить SoD" as UC2
}
M --> UC1
UC1 .> UC2 : <<include>>
@enduml
```

## C4 (PlantUML)

```text title="PlantUML — контейнеры"
@startuml
!include <C4/C4_Container>
Person(hr, "HR-специалист")
System_Ext(hrms, "HRMS")
System_Boundary(idm, "IdM") {
  Container(core, "Ядро", "Java", "Роли, заявки")
  ContainerDb(db, "БД", "PostgreSQL")
}
Rel(hrms, core, "Кадровые события", "Kafka")
Rel(core, db, "Читает и пишет", "JDBC")
@enduml
```

Контекст — `C4_Context` и `System`, компоненты — `C4_Component` и `Component`.
