## ТЗ по ГОСТ 34.602

Разделы (редакция 1989 года): 1 Общие сведения · 2 Назначение и цели · 3 Характеристика объекта автоматизации · 4 Требования к системе (в целом; к функциям; к видам обеспечения) · 5 Состав и содержание работ · 6 Порядок контроля и приёмки · 7 Подготовка объекта к вводу · 8 Требования к документированию · 9 Источники разработки. Действующая редакция — 2020 года.

**ТЗ — та же цепочка в другой упаковке:** устав → AS-IS → БТ, ФТ, НФТ, ИБ, данные, интеграции → вехи → ПМИ → миграция. Большие приложения — ссылками. Изменения после согласования — дополнениями.

## Шаблоны

Короткие, обязательные разделы помечены; «не применимо, потому что…» вместо пустоты. Шапка: **статус, версия, автор, утверждающий**. Ссылки вместо копирования. Обязательно: **ошибки и исключения**, НФТ, критерии приёмки, **открытые вопросы** (кто, срок), история изменений.

**Спецификация функции:** источник · триггер · сценарий · правила · ошибки · данные · интеграции · статусы · НФТ · приёмка. **Интеграция:** владельцы · параметры обмена · маппинг · ошибки и надёжность · НФТ · мониторинг · окружения.

</section>

<section>

## Docs-as-code

Markdown в git · pull request с ревью · диаграммы текстом (Mermaid, PlantUML) · контракты YAML рядом с кодом · проверки в CI (ссылки, контракты, стиль) · сайт собирается автоматически. Документация — часть DoD. Плюсы: история, ревью, синхронность с кодом. Минусы: порог входа для бизнеса. Частый гибрид: бизнес — вики, техника — git.

</section>

## Confluence

Дерево по слоям · стартовая страница с навигацией · шаблоны · **свойства страницы** (статус, владелец) + **отчёт свойств** = реестр документов · задачи Jira на странице и ссылки из историй · встроенные комментарии для ревью · фрагмент / вставка фрагмента вместо копирования · метки · история версий · архив вместо удаления.
