## Какой сценарий

| Сценарий | Главный вопрос | Первый результат | Ловушка |
|---|---|---|---|
| A. Новый проект | Что построить и зачем? | Цели с метриками, границы, стейкхолдеры, контекст | Начать с решения заказчика |
| B. Зрелая система | Что работает и почему так? | Карта системы, одна функция end-to-end, анализ влияния | Менять то, чего не понимаешь |
| C. Середина реализации | Где мы на самом деле? | Оценка состояния проекта | Новые требования поверх устаревших |
| D. Legacy | Как работает на самом деле? | Реестр находок с источником и уверенностью | Верить старой документации |
| E. Замена системы | Что нельзя потерять, как переключиться? | Инвентаризация + стратегия перехода | Потерять недокументированное поведение |
| F. Одна интеграция | Кто кому что передаёт и что при сбое? | Описание интеграции + контракт | Анализировать всю чужую систему |

</section>

## Первые дни — всегда

Доступы (вики, трекер, репозиторий, стенд, БД на чтение, логи) · своя зона ответственности (RACI) · источник истины · стейкхолдеры и встречи · реестр вопросов и глоссарий · последние решения (ADR, протоколы) · одна функция end-to-end · договорённость о первом результате через 2–4 недели.

**Правило:** сначала понять, почему так, — потом менять. Документ и статус задачи — гипотеза, проверка — на системе.

</section>

<section>

## A. Новый проект

Цель и границы → стейкхолдеры → ограничения → AS-IS → контекст → требования → TO-BE → системное проектирование. Явно записать, что **не** входит.

## B. Зрелая система

Доступы → владельцы → источник истины → C4 → API → БД → интеграции → бэклог → релизы → инциденты → логи → функция end-to-end → изменение.

## C. Середина реализации

Сверка: требования ↔ документация ↔ реализация ↔ тесты ↔ бэклог. Оценка состояния: реализовано · в работе · согласовано, не начато · изменилось · открытые решения · зависимости · расхождения.

</section>

<section>

## D. Legacy

Интерфейс → API → БД → логи → интеграции → код и конфигурация → пользователи. У каждой находки — источник и уверенность; правило подтверждено двумя источниками.

## E. Замена системы

Инвентаризация (включая отчёты и задания по расписанию) → gap-анализ (перенести / изменить / отказаться) → маппинг и пробная миграция → стратегия: разом, поэтапно, параллельно, постепенное вытеснение → переключение, откат, сверка.

## F. Одна интеграция

Провайдер и потребитель · владелец данных · SLA и объёмы · контракт · маппинг · ошибки и повторы · идемпотентность · безопасность · мониторинг · тестовый контур · порядок релиза.

</section>
