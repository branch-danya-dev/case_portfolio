## Роли

| Роль | Главный вопрос | Артефакты |
|---|---|---|
| БА | Что и зачем нужно бизнесу? | AS-IS, TO-BE, gap, БТ |
| СА | Что делает система, как обменивается данными? | Use cases, ФТ, НФТ, данные, статусы, API, маппинг, трассировка |
| PO | Что и в каком порядке — ради ценности? | Бэклог, цели спринтов |
| Архитектор | Из чего решение, на каких технологиях? | C4, ADR, НФТ (с СА) |

Граница БА/СА: **БТ не упоминают систему**, ФТ описывают её поведение. На малом проекте роли совмещает один человек.

**СА не решает сам:** конфликт стейкхолдеров → заказчик; выбор технологии → архитектор (ADR); ИБ против удобства → ИБ + заказчик; «ещё одна система» → РП, запрос на изменение. СА **готовит** решение, принимает — A.

</section>

## Этапы проекта

| Этап | Вопрос | Выход |
|---|---|---|
| Инициация | Зачем, границы? | Устав утверждён |
| Обследование | Как сейчас, что болит? | Проблемы подтверждены данными |
| Бизнес-анализ | Как должно быть? | БТ согласованы |
| **Системный анализ** | Что делает система? | ФТ согласованы, трассировка к БТ |
| **Проектирование** | Как устроено? | Согласовано архкомитетом и ИБ |
| Разработка | — | Истории по DoD |
| Тестирование | Работает как задумано? | Протокол испытаний |
| Внедрение | Как перейти без потерь? | Акт ввода |
| Эксплуатация | Цели достигнуты? | Метрики целей |

**Agile:** этапы 2–7 — в каждом инкременте; фундамент (контекст, интеграции, данные) — в начале. СА работает на 1–2 спринта впереди. **DoR** — готово к работе, **DoD** — готово к закрытию.

**Доработка:** потребность → уточнение → как сейчас → **анализ влияния** → варианты → требования → модель / API / БД → согласование → задачи → разработка → тесты и регресс → релиз → smoke → проверка на продуктиве → документация.

</section>

## Слои артефактов

```text
ЗАЧЕМ    устав, стейкхолдеры, глоссарий
ЧТО      AS-IS, TO-BE, gap, БТ
         use case, ФТ, НФТ, справочники, бэклог
КАК      C4, данные, статусы, ADR
         интеграции, sequence, маппинг, API
ЗАЩИТА   требования ИБ
ЗАПУСК   миграция, план внедрения
ПРОВЕРКА ПМИ, тест-кейсы
```

Требования идут **вниз** (цель → БТ → ФТ → контракт → тест), вопросы — **вверх**.

**Минимум для малого проекта:** цель с метрикой + границы · TO-BE (если меняется работа людей) · ФТ/истории с критериями приёмки · модель данных · контекст + интеграции + контракты · статусные модели · приёмочные сценарии.

</section>

## RACI

| | Смысл | В строке |
|---|---|---|
| **R** Responsible | Делает | ≥ 1 |
| **A** Accountable | Отвечает, утверждает | **ровно 1** |
| **C** Consulted | Консультирует (двусторонняя связь) | 0+ |
| **I** Informed | Информируется (односторонняя) | 0+ |

**Порядок:** строки = артефакты, столбцы = роли → сначала A → потом R → C только где нужна экспертиза → I кому нужен результат → проверить. **RASCI:** + S (Supportive). **DACI:** Driver, Approver, Contributors, Informed.

**Ошибки:** две A или нет A · нет R · все C · все I · фамилии вместо ролей · забыты ИБ и аудит.

**Кейс:** ФТ — R: СА, A: заказчик; НФТ, интеграции — A: архитектор; ролевая модель — A: ИБ.
