## Модели и ER

**Концептуальная** (сущности и связи) → **логическая** (атрибуты, ключи, кардинальности — СА) → **физическая** (типы, индексы — DBA).

`||` ровно один · `|o` ноль или один · `}o` ноль или много · `}|` один или много. 1:N — FK на стороне «много»; M:N — связующая таблица.

Проверять на неудобных случаях: повторный приём, совместительство, история, аудит. **Не склеивать** человек / трудоустройство / учётная запись.

</section>

## Ключи и нормализация

PK — идентифицирует строку · UK — бизнес-уникальность · FK — ссылка. Практика: **суррогатный PK + натуральный UK** (`identity_id` + `person_id`).

**1НФ** — атомарные значения, без списков · **2НФ** — зависимость от всего ключа · **3НФ** — нет зависимостей между неключевыми. «Ключ, весь ключ и ничего, кроме ключа». Денормализация — осознанно: отчёты, история, снимки.

</section>

## SQL

Порядок: FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT.

`IS NULL` (не `= NULL`) · `IN`, `BETWEEN`, `LIKE 'С%'` · `CASE WHEN … END` · `COALESCE`.

**JOIN:** INNER — пары; LEFT — все слева. **Без пары:** `LEFT JOIN b ON … AND <условие на b> WHERE b.id IS NULL` — условие на правую таблицу в **ON**, не в WHERE.

`COUNT(*)` — строки · `COUNT(col)` — не-NULL · `COUNT(DISTINCT col)`. WHERE — до группировки, HAVING — после.

**Подзапросы:** `IN`, скалярный, `EXISTS`. **`NOT IN` + NULL = пусто** → `NOT EXISTS`. CTE: `WITH x AS (…) SELECT …`.

**Окна:** `ROW_NUMBER() OVER (PARTITION BY … ORDER BY …)` — последняя запись в группе (`rn = 1` во внешнем запросе); `RANK` / `DENSE_RANK`; `LAG` / `LEAD`; `COUNT(*) OVER (PARTITION BY …)`.

</section>

## Транзакции

**ACID:** атомарность · согласованность · изоляция · долговечность.

| Уровень | Грязное | Неповтор. | Фантомы |
|---|---|---|---|
| Read Uncommitted | + | + | + |
| Read Committed | — | + | + |
| Repeatable Read | — | — | + |
| Serializable | — | — | — |

Потерянное обновление → оптимистическая блокировка (версия, 409 Conflict). Между системами — **не транзакция**, а идемпотентность, повторы, сага с компенсациями, outbox, сверка.

</section>

<section>

## Индексы

B-дерево: поиск, соединения, сортировка; цена — запись и место. Составной — **слева направо**. Мешают: функция над столбцом, `LIKE '%…'`, низкая избирательность. Уникальность — уникальным индексом. Аналитик даёт: сценарии поиска, частоту, объёмы, уникальность.

</section>

<section>

## НСИ

Паспорт справочника: назначение · **мастер-система** · **владелец** · потребители · ключ · доставка изменений · **даты действия** · **поведение при отсутствии значения** · контроль качества. Таблица соответствия кодов между системами. MDM, золотая запись.

**Кейс:** `org_unit` → timezone (FR-08), OU (AD), `abs_branch_code` (АБС); нет кода → бизнес-ошибка → задача в ServiceDesk.
