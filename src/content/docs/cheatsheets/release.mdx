## Среды

| Среда | Вопрос | Данные |
|---|---|---|
| DEV | Работает ли код | Синтетика, заглушки |
| TEST | По требованиям? Интеграции? | Синтетика |
| UAT | Принимает ли заказчик | Обезличенные |
| PREPROD | Готовы к продуктиву: объём, выкладка, откат | Обезличенный срез объёмом как в PROD |
| PROD | — | Реальные |

**Одна сборка на все среды** — отличаются конфигурация (адреса, флаги, расписания, лимиты) и секреты.
**Секреты** — в хранилище секретов, отдельно по средам; в конфигурации только имя. Не в коде, письмах, задачах.

## Кто выкладывается первым

**Первым — тот, кто должен понять новое.** Между выкладками всегда есть окно смешанных версий.

| Изменение | Первым |
|---|---|
| Новый метод, новое поле в запросе | Поставщик |
| Новое поле в ответе | Поставщик (если потребители — tolerant reader) |
| Новое значение enum, новый код ответа | Потребитель |
| Новый тип события, поле в событии | Потребитель |
| Обязательное поле, переименование, удаление | Расширение и сужение |

**Расширение и сужение:** добавить новое рядом со старым → перевести всех → удалить старое отдельным релизом.
**Скрипты БД** в релизе с приложением — только аддитивные: тогда откат приложения без отката схемы.

**Кейс:** релиз 1.0 — адаптер АБС раньше IdM (поставщик первым). CHG-01 — IdM с обработкой 429 раньше адаптера (потребитель первым), иначе повторится INC-01.

## Флаги и откат

**Выкладка ≠ выпуск:** фича-флаг включает функцию без новой выкладки — пилот, регионы, быстрый откат. Поведение описать в **обоих** положениях флага.

| Откат | Когда | Ограничение |
|---|---|---|
| Флаг | Функция работает неправильно | Код корректен при выключенном флаге |
| Версия | Версия неработоспособна | Схема БД совместима |
| Исправление вперёд | Откат невозможен или дороже | Время на исправление |

**Не вернуть откатом:** письма и SMS, записи в смежных системах, данные пользователей, опубликованные события. Назвать **точку невозврата**.

</section>

## Выпуск

- **Release notes** — по аудиториям: сопровождение, поддержка, пользователи, смежные команды; известные ограничения.
- **Go/no-go** — критерии заранее: тесты и дефекты, репетиция выкладки и отката, данные, алерты и runbook, люди предупреждены, смежные системы. Не выполнен — перенос.
- **Smoke** — минуты после выкладки: живо ли, связано ли с соседями; без реальных данных.
- **Проверка на продуктиве** — дни: решает ли задачу, по метрикам цели.
- **Hypercare** — первые недели: ежедневный разбор отклонений до критерия завершения.
