## Сопровождение

| | Цель | Кто |
|---|---|---|
| Инцидент | Быстро восстановить работу | L2, при необходимости L3 |
| Проблема | Найти и устранить корневую причину | L3, СА |
| Изменение | Исправить требования, контракты, систему | СА, владелец продукта |

**L1** — приём обращений · **L2** — диагностика по runbook, повторный запуск · **L3** — код, конфигурация, контракты · **СА** — «дефект или требование», анализ влияния, изменения.
Приоритет = влияние × срочность; срочность — ещё и бизнес-срок (в кейсе — дата выхода).

</section>

## Разбор инцидента: шесть вопросов

1. **Где ошибка** — алерт, логи по `traceId`, ответы систем.
2. **Что ожидалось** — ФТ, статусная модель, контракт.
3. **Какая система — источник** — что изменилось: релизы, конфигурация, нагрузка.
4. **Дефект или контракт** — не по требованиям → дефект; по требованиям, но не то → требования; смежная система не по контракту → контракт; ситуация не описана → пробел.
5. **Какие данные пострадали** — записи, очереди, задачи людям, сделанное вручную.
6. **Нужен ли повторный запуск** — причина устранена · тот же ключ идемпотентности · не сделано вручную · операция ещё нужна.

Исключённые версии (ложные следы, например пустой DLQ) — тоже записать.

</section>

## Анализ корневых причин

Хронология → «5 почему» до процесса, требований, проектирования, мониторинга, тестов → несколько причин → действия (исправляющие и предупреждающие) с владельцем и сроком → запросы на изменение → что сработало хорошо → проверка через время. Без поиска виноватых.

</section>

<section>

## Мониторинг, логи, runbook

**Метрики** на бизнес-вопрос: задержка, очереди, ошибки по интеграциям, ручные задачи, готовность к сроку.
**Алерт** = порог + приоритет + получатель + процедура.
**Логи:** структурированные, идентификаторы вместо ПДн, `traceId` во всех вызовах и в аудите (`traceparent`, W3C Trace Context).
**Runbook:** признаки → проверить → действия → эскалация.

**Кейс INC-01:** лимит адаптера (503 вместо 429, блокировка 120 с) + повторы пачкой → 7 из 175 в MANUAL. IdM действовала по FR-16 → нарушение контракта и пробел требований. Повтор — для 5, с тем же ключом; 2 созданных вручную — закрыть задачи, не повторять.
