## Рассказ о проекте (3–5 минут)

Контекст и цель с цифрами → **моя** роль → решение в 3–4 предложениях → сложность и как решил → результат.
Ответ на вопрос: определение → когда применять → пример из опыта.
**STAR:** Situation → Task → **Action (я)** → Result. Заготовить 4–5 историй: конфликт требований, неопределённость, ошибка в требованиях, сложный стейкхолдер, срочное изменение.

</section>

<section>

## Интеграция

Уточнить: зачем, как быстро, объём, мастер-система, нужен ли ответ, сколько получателей, ПДн.
Выбрать стиль: ответ нужен сразу → REST / gRPC; событие для многих → брокер; большие объёмы раз в сутки → пакет.
Описать: контракт → ошибки и повторы → идемпотентность → DLQ → безопасность → мониторинг и сверка.

</section>

<section>

## Sequence

Участники → успешный путь → ответы → `alt` на каждую ошибку (тайм-аут, отказ, дубль) → примечания. Результат оплаты — из webhook, а не из редиректа. Повтор — с ключом идемпотентности.

</section>

<section>

## Требования

Сначала назвать дефект, потом исправить. Дефекты: неизмеримо («быстро»), неоднозначно («все заинтересованные»), составное («и»), непроверяемо («удобно»), неполно (где, когда, в каком состоянии).
Просьба заказчика — это решение: вопросы «зачем» → проблема → варианты.
Gherkin: успешный сценарий + проблема + **права доступа**; конкретные данные, наблюдаемый результат.

</section>

## SQL-ловушки

| Ловушка | Правильно |
|---|---|
| `= NULL` | `IS NULL` |
| Условие на правую таблицу LEFT JOIN в WHERE | В `ON` |
| Агрегат в WHERE | `HAVING` |
| Поле не в GROUP BY | Группировать или агрегировать |
| `COUNT(поле)` | Не считает NULL |
| «Последний в группе» | `ROW_NUMBER() OVER (PARTITION BY … ORDER BY … DESC)` |

</section>
