## Уровни

| Уровень | Проверяет | Вход от аналитика |
|---|---|---|
| Модульное | Функции, классы | Бизнес-правила, границы |
| Интеграционное | Обмен между системами | Контракты, sequence, ошибки |
| Системное | Систему против требований | ФТ, НФТ, критерии, статусы |
| Приёмочное | Решает ли задачу заказчика | ПМИ, сценарии UAT, TO-BE |

**Виды:** функциональное · нагрузочное · стресс · безопасности · отказоустойчивости · удобства · совместимости · регрессионное · smoke · позитивное / негативное.
**Пирамида:** много модульных, меньше интеграционных, мало сквозных.

</section>

<section>

## Роль аналитика

Проверяемые требования и критерии · модели для тестов · ревью тестов по трассировке · тестовые данные для краевых случаев · разбор спорных дефектов (код или требование?) · участие в приёмке.
**Серьёзность** — влияние на систему; **приоритет** — срочность для бизнеса.

</section>

## Тест-дизайн

| Техника | Суть | Пример кейса |
|---|---|---|
| Классы эквивалентности | Одно значение на группу с одинаковым поведением | `eventType`: 3 допустимых класса + недопустимые → DLQ |
| Граничные значения | На границе и рядом | Логин 19 / 20 / 21; создание за 4 / 3 / 2 раб. дня |
| Таблица решений | Колонка = комбинация условий = тест | Повторы FR-16: ответ × попытка |
| Переходы состояний | Разрешённые + запрещённые | ACTIVE → CREATED_DISABLED отклонено |
| Попарное | Все пары значений вместо полного перебора | 48 комбинаций → от 12 тестов |

**Из моделей:** use case — альтернативы и исключения · статусы — переходы · sequence — ветки `alt` · правила — таблица решений · НФТ — нагрузка, отказ, безопасность.
Нельзя сформулировать ожидаемый результат — требование неполное.

</section>

<section>

## ПМИ

Объект · цель · объём (виды + проверки со ссылками на требования) · условия (стенд, заглушки, данные, время) · участники · порядок · **измеримые критерии успешности** · отчётность (протокол, заключение, подписи).
Кейс: 50 синтетических сотрудников, сдвиг времени планировщика; критерии — все M пройдены, нет дефектов 1–2.

</section>

<section>

## UAT

Реальные пользователи · сценарии от процесса TO-BE, а не от экранов · данные, похожие на реальные · аналитик сопровождает.

| Замечание | Что делать |
|---|---|
| Дефект | Исправить по критичности |
| Дефект требования | Решение владельца |
| Пожелание | В бэклог |
| Непонимание | Обучение, удобство |

</section>
