Маршрут рассчитан на 6 недель по 5–7 часов в неделю. Если у вас уже есть опыт (например, в банке), проходите быстрее: читайте «Кратко» и вопросы, а подробно — только темы, где ответ не получился сразу.

Порядок повторяет жизненный цикл проекта: от «зачем» к «как» и «как проверить». Каждая неделя заканчивается практикой на кейсе IDM-JOINER.

<Steps>

1. **Неделя 1. Роль и требования.**
   Темы: [СА и БА](/role/sa-vs-ba/), [жизненный цикл](/role/lifecycle/), [артефакты по этапам](/role/artifacts-by-stage/), [RACI](/role/raci/); [вход в проект](/onboarding/) — шесть сценариев первых дней; затем выявление требований, уровни и свойства требований.
   Практика: прочитать [устав](/case/00-project/project-charter/) и [RACI кейса](/case/00-project/stakeholders-raci/). Ответить: кто утверждает ФТ и почему ролевую модель утверждает ИБ?

2. **Неделя 2. Процессы и требования к системе.**
   Темы: [BPMN 2.0](/processes/bpmn/), AS-IS и TO-BE, gap-анализ; user stories, use cases, критерии приёмки, приоритизация, трассировка.
   Практика: сравнить [AS-IS](/case/01-business/as-is/) и [TO-BE](/case/01-business/to-be/); нарисовать в [BPMN-редакторе](/tools/bpmn-editor/) процесс Leaver (увольнение).

3. **Неделя 3. Диаграммы.**
   Темы: какую диаграмму выбрать, use case, activity, sequence, state, class, C4, DFD; практикум «как нарисовать».
   Практика: в [песочнице Mermaid](/tools/mermaid-sandbox/) — activity генерации логина (FR-06) и state трудоустройства; разобрать [все диаграммы кейса](/case/diagrams/).

4. **Неделя 4. Данные.**
   Темы: модели данных и ER, ключи и нормализация, SQL (SELECT → JOIN → агрегаты → подзапросы → оконные функции), транзакции, индексы, НСИ.
   Практика: [модель данных кейса](/case/03-architecture/data-model/) и SQL-задачи на её основе.

5. **Неделя 5. Интеграции и архитектура.**
   Темы: стили интеграции, REST и ошибки, SOAP, gRPC, GraphQL, Kafka и RabbitMQ, паттерны надёжности, контракты, безопасность; НФТ, ADR, монолит и микросервисы.
   Практика: [карта интеграций](/case/04-integrations/integration-map/), [сценарии](/case/04-integrations/scenarios/), [API адаптера АБС](/case/04-integrations/api-abs-adapter/) — объяснить, зачем `Idempotency-Key`.

6. **Неделя 6. Документирование, методологии, тестирование и собеседование.**
   Темы: ТЗ по ГОСТ 34, docs-as-code, Scrum / Kanban / гибриды, тест-дизайн, ПМИ, UAT; вопросы по темам и практические задачи.
   Практика: ответить на 15 вопросов по кейсу из [шпаргалки кейса](/case/cheatsheet/#10-вопросы-для-самопроверки-и-упражнения); пройти тренажёр по всем темам.

</Steps>

Темы без ссылок ещё пишутся — их статус виден на [главной](/). Маршрут будет обновляться по мере готовности разделов.
