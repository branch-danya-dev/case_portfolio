# Справочник системного аналитика

Локальный сайт: шпаргалка и гайд в одном. Краткие выжимки и подробные разборы по темам профессии, маршрут обучения из 10 модулей, интерактивные инструменты, банк вопросов к собеседованию, аттестация (Foundation Exam и System Analyst Final со сквозным кейсом) и полностью разобранный учебный кейс IDM-JOINER. Работает **полностью офлайн**: без CDN, внешних шрифтов и сетевых запросов. Прогресс и данные инструментов хранятся только в вашем браузере.

Стек: Astro 7, Starlight, React (острова), Mermaid, bpmn-js, PlantUML (на этапе сборки), Pagefind (поиск).

## Запуск

Нужен Node.js 22.5+ (проверено на 24): скрипты проверки используют встроенный `node:sqlite` и `WebSocket`.

```bash
npm install
npm run build     # сборка + проверка ссылок, офлайна, всех Mermaid-диаграмм, эталонов SQL-тренажёра, API Lab и аттестации
npm run preview   # http://localhost:4321 — здесь работает поиск
```

### Проверки

| Команда | Что проверяет | Когда |
|---|---|---|
| `npm run build` | Ссылки и якоря, отсутствие внешних загрузок в `dist/`, отрисовку всех Mermaid-диаграмм (headless Chrome), эталоны SQL-тренажёра, задания API Lab, аттестацию (`check-assessment.mjs`: выборка, баллы, эталоны практики) | Каждая сборка |
| `npm run check:a11y` | Доступность по WCAG 2.1 A/AA (axe-core) в тёмной и светлой теме; `-- --all` — все страницы | Нужен запущенный `npm run preview` |
| `npm run check:requests` | Что в браузере ни один запрос не уходит за пределы сайта (с ленивыми загрузками); `-- --all` — все страницы | Нужен запущенный `npm run preview` |

Проверкам с браузером нужен установленный Chrome или Chromium (путь можно задать в `CHROME_PATH`); без него они пропускаются с предупреждением. Chrome запускается с временным профилем.

Для разработки — `npm run dev` (живая перезагрузка; поиск в dev-режиме не работает, это ограничение Pagefind).

### PlantUML (необязательно)

Диаграммы PlantUML уже отрисованы в SVG и лежат в `public/diagrams/`, поэтому сайт собирается без Java. Чтобы перерисовывать их после правок `.puml`:

1. Установите Java 11+ (проверено на 17).
2. Один раз выполните `npm run setup:plantuml` — скачает `vendor/plantuml.jar`. Это единственный шаг, которому нужна сеть.
3. Дальше `npm run dev` и `npm run build` перерисовывают изменённые диаграммы сами. Принудительно — `npm run render:puml`.

Без Graphviz используется встроенный в PlantUML layout-движок Smetana. Если Graphviz установлен (`dot` в PATH), скрипт возьмёт его.

## Как добавить страницу

1. Скопируйте `templates/topic-page.mdx` в `src/content/docs/<раздел>/<slug>.mdx`. Эталон заполнения — `src/content/docs/processes/bpmn.mdx`.
2. Заполните блоки по порядку: «Кратко» → когда применять → как делать → нотация → пример из кейса → ошибки → вопросы → связанные темы.
3. Порядок в сайдбаре — `sidebar.order` во frontmatter.
4. Если раздел новый, поставьте ему `ready: true` в `src/sections.mjs`: он появится в сайдбаре и на главной.
5. `npm run build` — сборка упадёт на битой ссылке или внешней загрузке.

Ссылки только абсолютные: `/processes/bpmn/`. Диаграмма Mermaid — обычный блок кода с языком `mermaid`, подпись — `title="…"`.

## Как добавить вопрос к собеседованию

Вопросы лежат в `src/data/questions/<тема>.yaml`, по файлу на тему:

```yaml
title: BPMN 2.0
page: processes/bpmn
items:
  - id: bpmn-token            # латиница, цифры, дефис; уникален
    level: middle             # junior | middle | senior
    question: Что такое токен?
    tags: [семантика]
    answer: |                 # Markdown: списки, таблицы, **жирный**
      Воображаемая метка, которая…
```

На странице темы вопросы выводит `<InterviewQuestions topic="bpmn" />`. Те же записи использует тренажёр.

## Как добавить задание в аттестацию

Контент — в `src/data/assessment/` (TS-модули), дизайн — в `ASSESSMENT.md`.

- **Теория** — `theory-foundation.ts` или `theory-final.ts`: `single`, `multiple`, `order`, `match`. Задание — ситуация, а не «что такое X». Обязательно: `competency`, `difficulty`, `explanation`, `refs` (слаги страниц).
- **Практика** — `practice.ts`: `sql` (эталонный запрос), `http` (критерии по журналу учебного сервера и эталонные curl-запросы), `json-schema`, `openapi` (проверки структуры и эталон), `text` (рубрика для самопроверки).
- **Кейс** — файл `cases/<id>.ts` с материалами и заданиями, БД — `cases/<id>.sql`; кейс подключается в `index.ts` и в `exams.ts` (`cases`).
- Схема экзамена — `exams.ts`: доли разделов и правила выборки по компетенциям.

`npm run build` запускает `scripts/check-assessment.mjs`: если пула не хватает для схемы, эталон не проходит свою проверку или ссылка ведёт на несуществующую страницу, сборка упадёт.

## Как добавить термин в глоссарий

`src/data/glossary.yaml`:

```yaml
- id: token
  term: Токен
  en: Token
  definition: …
  topic: processes
  seeAlso: [bpmn]
  notToConfuse: …   # необязательно
  match: [токен*]    # необязательно: как термин пишется в текстах
```

### Подсказки на страницах

При сборке плагин `src/plugins/remark-terms.mjs` находит на каждой странице первое упоминание каждого термина глоссария, показывает при наведении, фокусе или касании его определение и добавляет в конец страницы блок «Термины на этой странице». Определения берутся только из `glossary.yaml` — правьте их там. Подсказок нет в глоссарии, инструментах, шпаргалках и на главной.

Как термин ищется в тексте (`match`):

| Запись | Что найдёт |
|---|---|
| `БА` | Ровно «БА» с учётом регистра — для аббревиатур |
| `~webhook` | «webhook», «Webhook» — точное слово без учёта регистра |
| `статусн* модел*` | «статусная модель», «статусной модели»… — `*` = любое окончание, без учёта регистра |
| `/(FR\|NFR)-\d+/` | Регулярное выражение |

Без `match` термин всё равно ищется, если он — аббревиатура в скобках (`Бизнес-аналитик (БА)`) или одно латинское слово (`RACI`, `Kafka`). Внутри кода, заголовков, ссылок и компонентов вроде `CaseRef` подсказки не ставятся.
