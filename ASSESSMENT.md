# Аттестация: дизайн

Документ для разработки. Описывает, как устроен раздел «Аттестация» (`/assessment/`), где лежит контент, как работают выборка, проверка и подсчёт баллов. Пользовательское описание — на страницах раздела.

## Зачем и чем отличается от тренажёра

| | Тренажёр собеседования (`tools/interview-trainer`) | Аттестация (`assessment/`) |
|---|---|---|
| Вопрос | «Готов ли я отвечать на вопросы?» | «Освоил ли я программу и могу ли применять?» |
| Материал | Банк вопросов собеседования (`src/data/questions`) | Отдельный банк заданий (`src/data/assessment`), не дублирует вопросы |
| Ответ | Сразу показан, самооценка «знаю / не знаю» | Скрыт до завершения попытки |
| Практика | Нет | SQL, HTTP-запросы, JSON Schema, OpenAPI с автоматической проверкой |
| Результат | Прогресс по темам | Балл, профиль компетенций, слабые места, история попыток |

## Экзамены

| Экзамен | Цель | Состав | Порог «пройден» |
|---|---|---|---|
| Foundation (`foundation`) | Фундамент уровня junior после модулей 1–4 маршрута | Теория 60% (выборка по компетенциям), практика 40% (SQL, API, JSON Schema, OpenAPI, требования) | 70% |
| System Analyst Final (`final`) | Провести задачу через жизненный цикл | Теория 25%, техническая практика 35%, сквозной кейс 40% | 75% |

Доли — вес раздела в итоговом балле, а не число заданий.

## Контент (`src/data/assessment/`)

TS-модули, как `sql-tasks.ts` и `api-lab/exercises.ts`: типы проверяются при сборке, валидаторы описываются конфигурацией.

| Файл | Что внутри |
|---|---|
| `types.ts` | Типы заданий, экзаменов, кейсов |
| `competencies.ts` | 11 компетенций: id, название, страницы для повторения |
| `theory.ts` | Банк теоретических заданий (ситуационные: выбор, множественный выбор, порядок, сопоставление) |
| `practice.ts` | Практические задания с автоматической проверкой |
| `cases/<id>.ts` | Экзаменационный кейс: пакет материалов + задания кейса |
| `cases/<id>.sql` | Учебная БД кейса (SQLite) |
| `exams.ts` | Схемы экзаменов: разделы, доли, правила выборки, пороги |

### Задание

```ts
{
  id, type, exams: ['foundation' | 'final'], competency, difficulty: 1 | 2 | 3, weight,
  prompt,            // Markdown
  options?, answer?, // для single / multiple / order / match
  check?,            // конфигурация автоматической проверки: sql | http | json-schema | openapi | text-lint
  rubric?,           // критерии самопроверки для открытых ответов
  explanation,       // показывается только после завершения
  refs,              // страницы справочника для повторения — только после завершения
}
```

Типы: `single`, `multiple`, `order`, `match`, `sql`, `http`, `json-schema`, `openapi`, `text` (открытый ответ с рубрикой, частично — с детерминированной проверкой).

## Движок (`src/lib/assessment/`)

| Модуль | Что делает |
|---|---|
| `rng.ts` | Детерминированный генератор по seed: попытку можно восстановить |
| `select.ts` | Сборка попытки по схеме экзамена: обязательный минимум по каждой компетенции, затем случайная выборка внутри |
| `score.ts` | Балл задания 0…1 по типу, разделы, итог с долями, профиль компетенций, интерпретация |
| `validators.ts` | Проверки без DOM: сравнение результатов SQL, журнал запросов к учебному серверу, ajv, структура OpenAPI, линтер требований |
| `attempts.ts` | Хранение попыток через `src/scripts/storage.ts` |

Движок не зависит от React. UI — `src/components/assessment/`, острова `client:only`.

## Попытка

```text
начать → задания (ответы сохраняются сразу) → обзор незаполненных → завершить (подтверждение) →
результат → разбор (эталон, объяснение, ссылки) → самопроверка открытых ответов по рубрике
```

- В localStorage (`sa:assessment:attempts`) хранятся id заданий, ответы, seed, даты, итог и баллы по областям — без текстов заданий.
- Незавершённая попытка одна на экзамен; при открытии страницы она восстанавливается.
- До завершения UI не показывает эталоны, объяснения, правильные варианты и ссылки на разборы. Сайт статический и офлайн, поэтому ответы физически есть в JS-бандле: защита от случайного подсматривания, а не от намеренного.
- Открытые ответы оцениваются самопроверкой после завершения; до неё итог помечен как предварительный.

## Интерпретация

| Балл | Интерпретация |
|---|---|
| < 60% | База не закреплена |
| 60–74% | Фундамент junior |
| 75–84% | Уверенный junior |
| 85–92% | Сильная подготовка junior, готовность к задачам уровня middle |
| 93%+ | Высокий результат по программе |

Это оценка освоения материалов справочника, а не профессиональная сертификация и не грейд на рынке.

## Экзаменационный кейс

Итоговый кейс — **не IDM-JOINER**. Кейс v1 — «LIMITS»: управление лимитами и временной блокировкой карты в мобильном банке. Пакет: письмо заказчика, текущий процесс, требования, фрагмент OpenAPI, схема и строки БД, лог, интеграции, старый ADR, замечание QA, инцидент, запрос на изменение. Заложены: неоднозначное требование, несовместимое изменение API, пропущенный сценарий ошибки, расхождение документации и реализации, проблема данных, сбой в продуктиве, необходимость анализа влияния.

Второй кейс добавляется файлом `cases/<id>.ts` и строкой в `exams.ts`.

## Проверки

`scripts/check-assessment.mjs` (в `prepare:assets`):
- уникальность id, корректность ссылок на компетенции, варианты и ответы в допустимых границах;
- в пуле каждой компетенции хватает заданий для схемы экзамена;
- 2000 случайных выборок: каждая покрывает обязательные компетенции, без повторов;
- идеальные ответы дают 100%, пустые — 0%, итог не зависит от порядка заданий;
- эталоны SQL выполняются на БД и проходят собственную проверку, эталонные HTTP-запросы проходят на учебном сервере, эталоны JSON Schema и OpenAPI проходят валидаторы.
